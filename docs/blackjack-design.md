# molsino Blackjack — 개발 설계 v0.4

작성일: 2026-09-15 · 갱신일: 2026-09-17 · 상태: S10.5 금액 입력·게임 오버 경계 패치 완료

구체적인 창 API, 입력 정책, 모듈 계약, 저장·테스트 설계는 [기술 설계서](blackjack-technical-design.md)를 따른다.

## 1. 제품 방향

업무용 창 위에 작은 펫처럼 띄워 두고, 필요할 때 짧게 플레이하는 로컬 싱글플레이 블랙잭. 화면 대부분을 투명하게 비우고 카드·점수·잔액·동작만 흑백으로 표시한다.

### 사용자 요구사항

- 다른 앱 위에 떠 있는 작은 오버레이.
- 위치와 화면 크기를 사용자가 조절.
- 배경은 최대한 투명하게, 색상은 흰색과 검은색으로 제한.
- 컴퓨터 딜러와 로컬에서 싱글플레이.
- 최초 잔액 $100, 최소 베팅 $1. 베팅액 증감과 카지노식 보험·배당·추가 행동 지원.

### 이번 설계의 기본 제안

- 금액은 게임 안에서만 쓰는 가상 달러.
- Electron + TypeScri DIP로 macOS와 Windows를 함께 지원한다. 화면·게임 엔진·저장은 공유하고 macOS에서 먼저 개발·검증한다.
- MVP부터 Hit, Stand, Double, Split, Insurance, Even Money, Late Surrender를 제공한다.
- 소리·알림·큰 승리 효과 없이 결과 한 줄만 표시.

## 2. 오버레이와 조작

### 창

창 크기는 화면 배율에 독립적인 DIP 단위이며 Electron에서 OS별 물리 픽셀로 변환한다.

| 항목 | 제안값 / 동작 |
| --- | --- |
| 기본 크기 | 280 × 180  DIP |
| 최소 / 최대 | 220 × 150 / 420 × 280  DIP |
| 이동 | 상단의 짧은 드래그 영역을 잡아 이동 |
| 크기 조절 | 모서리 핸들로 조절, 호버 시 핸들 표시 |
| 표시 위치 | 일반 앱 창 위에 유지, 사용자가 끄기 가능 |
| 접기 | 내부 접힘 상태는 유지하되, 오해를 낳은 헤더의 `▁` 접기 버튼은 표시하지 않음 |
| 숨기기 / 복원 | 헤더 `−` 버튼·전역 Alt+백틱으로 숨기기. 메뉴 막대/트레이에서 복원 |
| 실행 중 설정 | 위치, 펼친 크기, 색상 모드, 불투명도, 접힘 여부, 클릭 통과. 앱을 새로 켜면 모두 기본값으로 초기화 |
| 모니터 변경 | 저장 위치가 화면 밖이면 현재 화면 안으로 복귀 |

크기 변경 시 단순히 화면 전체를 축소하지 않는다. 카드 간격과 줄바꿈을 먼저 조절하고 본문 글씨는 최소 11 DIP, 버튼의 실제 클릭 영역은 최소 24 × 24 DIP를 유지한다. 카드가 많으면 카드 영역만 가로 스크롤하고 합계와 동작 버튼은 계속 보인다.

### 투명도와 흑백

- 창 배경 기본 알파 0%, 테두리와 그림자 없음.
- 전경은 검정 또는 흰색 중 수동 선택. 반대색의 얇은 외곽선으로 복잡한 화면에서 글자 윤곽 유지.
- 펼친 창 우측 상단의 흑백 색상 전환 버튼에 마우스를 올리면 별도 불투명도 조절창이 나타난다. 조절창의 슬라이더로 전경 불투명도를 조절한다. 기본 65%, 범위 20–100%(5% 단위)이며 20% 미만으로 내려 완전히 안 보이게 할 수 없다. 창 배경은 계속 투명하다.
- 조절창은 색상 버튼의 좌우 중 화면 작업 영역을 벗어나지 않는 쪽으로 열고, 위아래도 작업 영역 안에 맞춘다. 버튼에서 조절창으로 마우스를 옮기는 동안 유지되며 둘 다 벗어나면 닫힌다.
- 게임 창에 마우스가 올라오면 전경 100%, 벗어나면 0.8초 후 설정값으로 복귀한다. 조절창에서 슬라이더를 조작하는 동안에는 선택한 불투명도를 즉시 미리 본다.
- 가독성 보조 옵션: 정보 영역 뒤에만 반대색 배경을 0–20% 알파로 추가. 기본 0%.
- 모든 문양과 상태는 흑백. 승패는 색 대신 `승리`, `패배`, `무승부`와 금액으로 구분.
- 투명 배경에서도 카드 숫자는 전부 읽혀야 하므로 카드 전체를 겹치지 않는다.

### 입력 모드

1. **플레이 모드:** 카드와 버튼 영역에서 마우스로 조작한다. 드래그와 크기 조절도 이 모드에서 사용한다.
2. **클릭 통과 모드:** 창 전체의 마우스 입력을 아래 앱으로 통과시킨다. 이 상태에서는 오버레이 안의 버튼도 누를 수 없으므로 메뉴 막대/트레이에서 플레이 모드로 복귀한다.
3. **접기 / 숨기기:** 진행 중인 판을 초기화하지 않는다. 창의 표시만 바뀌며 딜러 자동 진행과 각 단계의 저장은 계속된다. 다시 펼치거나 복원하면 그때의 최신 판을 보여 준다.

투명한 픽셀이라고 자동으로 클릭이 통과한다고 가정하지 않는다. MVP는 창 전체의 명시적인 클릭 통과 모드를 보장하고, 부분 통과는 별도 검증 후 추가한다. 전역 게임 단축키는 MVP에서 제외해 다른 앱에서 입력하는 키가 게임 동작을 일으키지 않게 한다. 예외인 Alt+백틱은 창을 숨기기만 하며 토글·복원·게임 동작을 하지 않는다. 이미 숨겨졌다면 변화가 없고, 복원은 메뉴 막대/트레이에서 한다. 다른 앱에서 해당 단축키를 이미 점유했다면 등록하지 못할 수 있으며 메뉴 숨기기·복원은 계속 이용할 수 있다. 자동으로 창을 띄우거나 복원할 때 다른 앱의 키보드 포커스를 빼앗지 않는 것이 목표다.

전체 화면 앱, Spaces 이동, 다중 모니터에서의 표시 방식은 초기 창 프로토타입에서 확인한다. 일반 창 위에 유지되는 기능과 전체 화면 위 표시 가능 여부는 구분해 검증한다.

## 3. 작은 화면 구성

아래 테두리는 영역을 설명하기 위한 것으로 실제 창에는 표시하지 않는다. 카드도 큰 사각형 대신 작은 숫자와 문양으로 표현한다.

```text
┌────────────────────────────────┐
│ ⠿  $95.00              −   ⋯   │
│ 딜러   9♠  ?          공개 9   │
│ 나     A♣  7♥         8 / 18   │
│ 베팅 $5                       │
│ [히트]   [스탠드]   [더블]     │
└────────────────────────────────┘
```

| 상태 | 표시 내용 | 가능한 조작 |
| --- | --- | --- |
| 베팅 전 | 잔액, 마지막 결과, 베팅 금액 | − / +, 증감 단위 선택, 직접 입력, 프리셋, 딜 |
| 보험 선택 | 원 베팅, 보험 한도 또는 이븐 머니 | 보험액 조절 / 구매 / 거절 또는 이븐 머니 / 유지 |
| 플레이어 차례 | 딜러 공개 카드, 내 카드와 합계, 이번 베팅 | 히트 / 스탠드 / 더블, 추가 메뉴의 스플릿 / 서렌더 |
| 딜러 차례 | 공개된 딜러 카드와 합계 | 게임 버튼 비활성 |
| 결과 | 양쪽 카드, `승리 +$5.00` 등의 순손익 | 다음 판 |
| 접힘 | `$95.00 · 진행 중` 또는 잔액과 펼치기 표시 | 펼치기 |
| 게임 오버 | 정산 후 잔액이 $1.00 미만이면 `$0.99 · 게임 오버` 같은 안내 | 새 게임 |

- 라운드 중 잔액은 베팅금을 이미 뺀 사용 가능 금액이다.
- `?`는 숨겨진 카드이며 딜러 합계도 공개 카드만 반영한다.
- 소프트 핸드는 `8 / 18`처럼 A를 1 또는 11로 셌을 때의 합계를 함께 보여준다.
- 결과 금액은 보험과 모든 핸드를 합친 라운드 순손익이다. 본 베팅 무승부라도 보험 손실이 있으면 음수다. 팝오버에 핸드별 결과와 보험 결과를 표시한다.
- 스플릿 시 활성 핸드만 크게 표시하고 `핸드 1/2 · $5`와 다른 핸드의 작은 합계를 함께 표시한다. 진행 순서는 엔진이 정하며 완료된 핸드는 읽기 전용이다.
- 추가 메뉴의 스플릿·서렌더는 유효할 때만 활성화한다. 보험 단계는 액션 줄을 대체해 창 크기를 유지한다.
- 더블이 불가능하면 비활성 상태와 간단한 설명을 제공한다.
- 베팅 금액 숫자칸을 누르면 같은 자리에서 텍스트 필드로 바뀐다. 평소에는 오버레이가 키보드 포커스를 받지 않고, 사용자가 금액을 편집하는 동안에만 입력을 받는다.

## 4. 게임 규칙: 카지노식 6덱 테이블

카지노마다 덱 수·소프트 17·배당·스플릿 제한이 다르다. 아래 조합을 이 게임의 고정 테이블 규칙으로 선택한다. 특정 카지노의 모든 테이블을 그대로 복제하는 것은 아니다. 시작 자금 $100과 최소 베팅 $1은 사용자 요구대로 유지한다.

실제 카지노 안내에서 자연 블랙잭의 3:2 또는 6:5 배당, 같은 점수 카드의 스플릿, 보험의 2:1 배당을 확인할 수 있다. 이 게임은 그중 3:2 배당을 채택한다. [Venetian 블랙잭 안내](https://www.venetianlasvegas.com/resort/casino/table-games/how-to-play-blackjack.html)

### 테이블 규칙

| 항목 | 적용 규칙 |
| --- | --- |
| 시작 금액 | 새 게임 $100.00, 가상 달러 |
| 기본 베팅 | 잔액이 $1.00 이상일 때 최소 $1.00, 센트 단위 직접 입력 가능. 상한은 현재 사용 가능 잔액 |
| 슈 | 6덱 312장, 동일 문양·숫자 카드가 6장씩 존재 |
| 셔플 | 새 슈 시작 때 섞음. 234장(75%) 사용 후 현재 판을 끝내고 다음 판 전에 재셔플. 판 중간 셔플 없음 |
| 안전 여유 | 새 판 시작 시 남은 카드가 78장 미만이어도 재셔플. 최대 4핸드 및 딜러 진행에 충분한 여유 확보 |
| 배분 | 플레이어 → 딜러 공개 → 플레이어 → 딜러 비공개, 미국식 홀 카드와 피크 사용 |
| 점수 | 2–10은 숫자, J/Q/K는 10, A는 버스트하지 않는 범위에서 11 또는 1 |
| 자연 블랙잭 | 스플릿 전 최초 두 장의 A + 10점 카드, 순이익 3:2 |
| 일반 승리 / 무승부 | 순이익 1:1 / 원금 반환 |
| 딜러 | 16 이하면 히트, 소프트 17을 포함해 17 이상 스탠드(S17) |
| 히트 | 한 장 추가. 21이면 자동 스탠드, 21 초과면 해당 핸드 패배 |
| 더블 다운 | 두 장에서 점수 제한 없이 허용. 해당 핸드 베팅만큼 추가 지불 후 한 장만 받고 종료. 스플릿 후 허용(DAS), 스플릿 A는 제외 |
| 스플릿 | 두 카드의 점수가 같으면 동일 베팅을 추가해 분리. 10/J/Q/K 조합도 허용. 재스플릿 포함 최대 4핸드 |
| A 스플릿 | 한 번만 허용, A 재스플릿 불가. 각 핸드에 한 장만 추가하고 종료, 히트·더블 불가 |
| 스플릿 후 21 | A + 10점이어도 일반 21로 취급, 1:1 지급 |
| 레이트 서렌더 | 딜러 블랙잭이 아닌 것이 확인된 후, 스플릿 전 최초 두 장에서만 허용. 원금 절반 반환 |
| 추가 규칙 | 5장 자동 승리 없음, 더블 금액 축소 불가. 더블·스플릿 추가금에는 기본 베팅 상한을 다시 적용하지 않음 |

78장 안전 여유와 셔플 시점은 이 게임의 구현용 선택이다. 각 물리 카드에는 고유 ID를 부여하고, 한 슈 안에서 같은 물리 카드를 다시 뽑지 않는다. Fisher–Yates 방식으로 편향 없이 섞고 OS 난수 공급원을 사용한다.

### 베팅액 올리기 / 내리기

```text
베팅  [−]  $5.00  [+]   [딜]
       단위 $1 ▾
```

- 기본 증감 단위는 $1. 팝오버에서 $1 / $5 / $10 / $25 중 선택한다.
- 금액 숫자칸을 클릭하면 그 자리에서 텍스트 필드로 바뀌고 현재 베팅액을 편집한다. Enter로 확정하고 Escape로 취소한다. 소수는 최대 두 자리까지 허용한다(예: `1`, `1.5`, `1.25`). 프리셋 $1 / $5 / $10 / $25 / $50 / $100은 해당 금액으로 설정한다.
- 직접 입력은 $1.00 이상, 현재 사용 가능 잔액 이하만 받는다. 빈 값·문자·음수·소수 셋째 자리·범위 밖 금액은 필드 옆에 오류를 표시하고 확정하지 않는다. 입력 중에는 기존 베팅액을 유지하고 딜을 막는다. 유효한 금액을 확정하면 저장된 값으로 숫자칸이 돌아오며, 취소하거나 필드 밖을 누르면 이전 베팅액으로 돌아온다.
- 최소·최대에 닿으면 증감을 경계값에서 멈춘다. 기존 −/+ 버튼의 증감 단위는 유지하되, 소수 베팅에서도 범위를 넘지 않는다.
- 베팅 변경은 딜 전만 가능. 딜 후 원 베팅은 고정되며 보험·더블·스플릿은 별도의 규칙에 따라 추가 차감한다.
- 이전 베팅을 기억하되 다음 판에서 잔액을 초과하면 가능한 최대 센트 금액으로 낮춰 표시한다. 자동 딜은 하지 않는다.
- 판 정산 후 사용 가능 잔액이 $1.00 미만이라면 게임 오버를 표시하고 다음 판·베팅·딜을 막는다. 정확히 $1.00은 최소 베팅으로 계속 플레이할 수 있다. 진행 중인 판은 잔액이 $1.00 미만으로 내려가도 끝까지 정산한다. 앱은 종료하지 않고 새 게임 선택을 제공한다.

### 인슈어런스와 이븐 머니

딜러 공개 카드가 A이면 비공개 카드를 확인하기 **전에** 보험 선택을 받는다. 보험은 원 베팅의 절반까지 가능한 별도 베팅이며 딜러 블랙잭일 때 순이익 2:1이다. [MGM 블랙잭 안내](https://www.mgmresorts.com/en/gamesense/guide-to-blackjack.html)

- `보험 안 함`과 `보험 $금액`을 표시하고, 금액은 $0.50 단위로 조절한다.
- 최대 보험액은 원 베팅의 절반과 사용 가능 잔액 중 작은 값을 $0.50 단위로 내린 값이다. 기본 제시액은 이 최대값. $0.50 미만이면 보험 구매 불가.
- 보험 구매 시 즉시 별도 차감한다. 딜러 블랙잭이면 보험 원금 포함 3배 반환, 아니면 보험액 손실. 본 게임 결과와 독립적으로 계산한다.
- 플레이어가 자연 블랙잭이고 딜러 A이면 `이븐 머니` 또는 `블랙잭 유지`를 제공한다. 이븐 머니는 추가 자금 없이 원 베팅의 순이익 1:1을 확정하고 종료한다.
- 자연 블랙잭에서는 별도 보험 UI 대신 이븐 머니를 제공한다. 이븐 머니를 거절하면 딜러 블랙잭 시 무승부, 아니면 3:2 지급한다.
- 딜러 공개 카드가 10점이면 보험을 제시하지 않고 바로 피크한다.

### 진행과 판정 순서

1. 기본 베팅을 차감하고 필요한 경우 새 슈를 만든 뒤 최초 카드를 배분한다.
2. 딜러 A이면 보험 또는 이븐 머니 선택을 먼저 받는다. 선택 없이 자동 진행하지 않는다.
3. 딜러 A/10점이면 피크한다. 보험을 즉시 정산한다. 딜러 블랙잭이면 공개하고 본 베팅을 패배 또는 자연 블랙잭 무승부로 정산한다. 이븐 머니는 고정 지급을 유지한다.
4. 딜러 블랙잭이 없고 플레이어 자연 블랙잭이면 3:2로 종료한다. 이븐 머니 선택 시에는 1:1만 지급한다.
5. 나머지 경우 히트·스탠드·더블·스플릿·서렌더 중 유효한 행동을 선택한다.
6. 스플릿 직후 왼쪽 핸드에 한 장을 주고 플레이를 끝낸 뒤 오른쪽 핸드에 한 장을 주고 진행한다. 재스플릿도 같은 왼쪽 우선 순서를 따른다. A 스플릿은 각 핸드에 한 장씩 주고 종료한다.
7. 핸드별 버스트·서렌더를 기록한다. 모든 핸드가 종료되면 딜러 카드를 공개하고, 비교할 살아 있는 핸드가 있을 때만 S17에 따라 드로우한다.
8. 각 핸드의 결과와 보험을 합쳐 라운드 순손익을 표시한다. 모든 핸드가 버스트/서렌더여도 이미 결정된 보험 결과는 유지한다.

### 돈 계산과 배당 예시

금액은 정수 센트로 저장한다. 직접 입력한 기본 베팅은 센트 단위이며, 보험은 기존 $0.50 단위다. 3:2 배당·서렌더 계산에서 반 센트가 생기면 최종 반환금을 1센트 단위로 반올림(정확히 반 센트는 올림)한다. 배당 비율은 **순이익** 기준이며 원금은 별도로 반환한다.

| $100에서 $5 베팅한 결과 | 총 투입금 | 총 반환금 | 최종 잔액 |
| --- | --- | --- | --- |
| 패배 | $5.00 | $0.00 | $95.00 |
| 무승부 | $5.00 | $5.00 | $100.00 |
| 일반 승리 | $5.00 | $10.00 | $105.00 |
| 자연 블랙잭 승리 | $5.00 | $12.50 | $107.50 |
| 더블 후 일반 승리 | $10.00 | $20.00 | $110.00 |
| 서렌더 | $5.00 | $2.50 | $97.50 |
| $2.50 보험, 딜러 블랙잭, 내 일반 패 | $7.50 | 보험 $7.50 | $100.00 |
| $2.50 보험 실패, 본 베팅 일반 승리 | $7.50 | 본 베팅 $10.00 | $102.50 |
| 이븐 머니 | $5.00 | $10.00 | $105.00 |
| $5씩 스플릿, 한 핸드 승리·한 핸드 패배 | $10.00 | $10.00 | $100.00 |

정산 후 잔액이 $1.00 미만이면 게임 오버로 다음 판을 막고 새 게임을 제안한다. 정확히 $1.00이면 $1.00 베팅으로 다음 판을 시작할 수 있다. 자동 충전이나 앱 종료는 하지 않는다. 새 게임은 잔액·슈·진행 중인 판을 초기화하므로 실행 전에 한 번 확인한다.

## 5. 구조

게임 엔진은 창이나 애니메이션 없이도 실행하고 검증할 수 있게 분리한다.

```text
React 화면 → Preload / IPC → Main GameStore → BlackjackEngine
                       ↓              ↑
                LocalSaveStore    ShuffleSource

OverlayWindowController ← 표시 설정 / 창 상태
```

위 다이어그램은 개념적인 데이터 흐름만 보여준다. 각 모듈의 정확한 이름, 책임 분리, 프로세스 경계는 [기술 설계서](blackjack-technical-design.md) §3을 따른다.

### 플랫폼 전략 — Electron 공통 구현

Electron + TypeScript + React/CSS로 화면·게임 엔진·로컬 저장을 두 OS에서 공유한다. Main은 게임 상태·창·저장을 소유하고 Renderer는 Preload의 제한된 IPC를 통해 명령을 보낸다. 딜러의 비공개 카드와 슈는 Renderer로 전달하지 않는다.

macOS에서 먼저 프로토타입을 검증하되 Windows 빌드·테스트도 처음부터 포함한다. OS 차이는 PlatformAdapter의 포커스·작업 공간·메뉴 막대/트레이 처리에 모은다. Windows용 엔진과 UI를 별도 언어로 다시 만들지 않는다.

투명 창은 frameless로 만들고 비활성 표시·상단 유지·전체 클릭 통과를 적용한다. Electron의 투명 창은 기본 리사이즈 제약이 있으므로 사용자 정의 핸들 + Main의 setBounds 방식을 양쪽 OS에서 먼저 검증한다. 크기 조절이 검증되지 않으면 필수 요구 미해결로 남긴다. [Electron 투명 창 제약](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)

패키징은 Electron Forge + Vite를 사용하고 macOS는 앱 서명·공증, Windows는 설치 패키지·서명을 검증한다. 자세한 프로세스·IPC·저장·테스트 계약은 [기술 설계서](blackjack-technical-design.md)를 따른다.

### 핵심 데이터

저장 세션은 카드 한 벌(6덱 슈, 물리 카드별 고유 ID), 진행 중인 라운드(핸드별 카드·베팅·상태, 보험/이븐 머니 결정, 정산 원장), 잔액·베팅 설정으로 구성된다. 창 표시 설정(위치·크기·색상·불투명도·접힘·클릭 통과)은 실행 중에만 유지하고 재실행 시 기본값으로 초기화한다. 정산 원장은 라운드 안에서 보험과 핸드마다 정확히 한 번만 지급되도록 항목별 고유 키를 쓴다. 비공개 딜러 카드는 엔진과 저장 데이터에 존재하지만 화면용 데이터에서는 공개 전까지 가린다.

정확한 필드명·타입·스키마 버전은 이 문서에서 별도로 정의하지 않는다. [기술 설계서](blackjack-technical-design.md) §6.1(명령·금액 계약)과 §7.2(저장 형식), 그리고 구현되는 `src/shared/contracts.ts`가 유일한 기준이다.

### 상태 전이

`베팅 → 최초 배분 → 보험/이븐 머니 선택(딜러 A) → 피크/자연 블랙잭 판정 → 핸드별 플레이 → 딜러 차례 → 정산 → 결과 → 베팅`

- 자연 블랙잭과 이븐 머니는 해당 판정 후 종료한다. 버스트는 해당 핸드를 종료하고 다음 핸드로 이동한다.
- 보험과 각 핸드 정산은 항목별 정확히 한 번 실행한다. 보험의 조기 정산을 최종 합산에서 다시 지급하지 않는다.
- 저장은 베팅 차감·배분 완료, 플레이어 동작, 딜러 카드 추가, 정산 등 의미 있는 상태 변경마다 한다.
- 재실행 시 덱 순서와 비공개 카드까지 같은 판으로 복원한다. 중간에 새 덱을 뽑지 않는다.
- 정산과 잔액 갱신은 하나의 저장 스냅샷으로 기록한다. 저장된 결과를 애니메이션 재생으로 다시 정산하지 않는다.
- 손상되거나 지원하지 않는 버전의 저장 파일은 보존하고 복구 또는 새 게임 선택을 표시한다.
- 클릭 통과 상태로 복원돼도 메뉴 막대/트레이에서 항상 해제할 수 있어야 한다.

## 6. 구현 순서와 완료 기준

### 1단계 — 창 프로토타입

가짜 카드와 잔액으로 투명 창을 만든다. 이동, 크기 조절, 메뉴 막대/트레이 복원, 클릭 통과, 포커스 동작부터 실제 데스크톱에서 확인한다.

**완료 기준:** 다른 앱을 사용하는 동안 작은 흑백 창이 유지되고, 크기·위치·불투명도를 바꿀 수 있으며 클릭 통과를 켰다가 메뉴에서 복구할 수 있다. 최소 크기에서도 버튼이 잘리지 않는다. 세부 검증 시나리오는 [기술 설계서](blackjack-technical-design.md) §11.1의 O-01~O-09를 따른다.

### 2단계 — 게임 엔진

6덱 슈, 점수, 베팅 증감, 보험·이븐 머니, 히트, 스탠드, 더블, 스플릿, 서렌더, 딜러, 항목별 정산을 §4의 규칙대로 구현한다.

**필수 검증:** 세부 항목은 [기술 설계서](blackjack-technical-design.md) §11.2에서 관리한다.

### 3단계 — 플레이 가능한 MVP

화면과 엔진을 연결하고 로컬 저장, 판 복원, 창 설정의 재실행 초기화, 새 게임을 완성한다.

**완료 기준:** 최초 $100에서 $1 이상 베팅해 여러 판을 끝낼 수 있고, 라운드 중 종료 후 재실행해도 같은 카드와 잔액으로 이어진다. 히트 전후·보험 선택 전후와 정산 후·스플릿 핸드 사이·더블 후·딜러 진행 중·정산 직후·판 사이 슈의 저장 복원을 검증한다. 이 체크포인트를 자동화한 시나리오는 [E2E 테스트 설계](e2e-test-plan.md)의 E2E-17이다.

### 4단계 — 사용성 점검

밝은 문서, 어두운 편집기, 복잡한 웹 화면을 배경으로 검토한다. 모니터 분리, 화면 가장자리, 접기와 복원, 전체 화면 앱 전환을 확인한다. 대기 상태에서 지속적인 렌더링 루프나 불필요한 타이머가 돌지 않도록 한다. 세부 시나리오는 [기술 설계서](blackjack-technical-design.md) §11.1의 O-06~O-08과 §11.3(성능 목표)를 따른다.

## 7. 첫 버전 범위 밖

- 멀티플레이, 계정, 서버, 실물 결제.
- 카드 이미지 리소스, 사운드, 장시간 애니메이션.
- 추가 사이드 베팅(21+3 등), 통계 대시보드, 여러 카지노 규칙을 선택하는 설정.
- 자동 배경 분석과 자동 색상 전환.
- 화면 캡처·공유에서 창을 제외하는 기능. 일반적인 투명 창은 캡처에 보일 수 있다.
