# 블랙잭 E2E 테스트 설계

**목적:** 기존 블랙잭 동작의 회귀 시나리오와 새 공용 상태 전환 시 확인할 경계를 정의한다.

**요약:** 대표 블랙잭 게임 흐름·세션 저장 복원의 시나리오와 픽스처를 다룬다. 구 미진행 시나리오 전체를 완성하는 일정은 폐기했으며 변경에 필요한 회귀를 선정한다. 창·Preload·Main의 공통 경계는 [메인 E2E 설계](../../main/e2e-test-plan.md), 현재 게임 테스트 범위는 [블랙잭 E2E 현황](e2e-implementation-status.md)을 따른다.

## 1. 목적과 범위

이 문서는 [블랙잭 제품 설계](product-design.md)의 플레이 가능한 MVP 완료 기준을 E2E 시나리오에 매핑한다. 제품 요구사항의 원문은 제품 설계서를 기준으로 한다.

범위는 **블랙잭 엔진과 AppStore·블랙잭 어댑터·IPC·UI·세션 저장의 통합**이다. E2E-18의 구 계획은 폐기했다. 신뢰 경계 E2E-21 및 오버레이 회귀는 [메인 E2E 설계](../../main/e2e-test-plan.md)가 관리한다. 실행 시점과 현재 상태는 [작업 세션 로드맵](../../work-session-roadmap.md)과 [블랙잭 E2E 현황](e2e-implementation-status.md)을 따른다.

### 테스트 계층 구분

같은 규칙을 두 계층에서 중복 검증하지 않는다.

| 계층 | 도구 | 대상 | 개수/속도 |
| --- | --- | --- | --- |
| 엔진·게임 저장·명령 스키마 | Vitest | `BlackjackCore` 순수 함수, 정산 원장, `SessionRepository`에 저장하는 블랙잭 상태와 명령 계약 | 다수, 빠름 — [블랙잭 기술 설계](technical-design.md)의 검증 항목 |
| 사용자 여정 (배관 검증) | Playwright `_electron` | 실제 앱 프로세스: Renderer 클릭 → Preload → Main IPC → AppStore·블랙잭 어댑터 → 엔진 → 저장 → 화면 반영 | 소수, 느림 — 이 문서의 시나리오 |

아래 표는 회귀 후보와 기존 식별자를 보존한다. N02 이후 E2E-01의 시작 화면과 E2E-16의 새 시작은 [메인 APP 시나리오](../../main/e2e-test-plan.md)의 메뉴·공용 초기화 계약으로 갱신한다. 게임별 규칙은 유지하며 구 S14~S15의 전체 완주를 요구하지 않는다.

E2E는 규칙의 모든 조합(예: 모든 배당 표 행, A 재스플릿 금지의 모든 경로)을 다시 검증하지 않는다. 각 주요 분기(블랙잭, 보험, 이븐 머니, 더블, 스플릿, 서렌더)당 **대표 경로 1개**만 실제 UI로 통과시켜 "전체 스택이 올바르게 연결됐다"를 증명하고, 세부 규칙 조합은 Vitest 픽스처가 책임진다.

## 2. 테스트 인프라 요구사항

시나리오는 실제 앱 프로세스의 Main/IPC/Renderer 경로에서 실행한다. 재현 가능한 카드 순서와 독립적인 저장 상태를 마련하고, 저장 복원은 동일한 `userData`에서 재기동해 검증한다. 훅의 현재 구현 여부와 정확한 파일 위치는 [E2E 구현 현황](e2e-implementation-status.md)을 따른다.

| 훅 | 요구사항 |
| --- | --- |
| 격리된 `userData` | 테스트 간 저장 파일이 충돌하지 않아야 한다. |
| 결정론적 슈 주입 | 특정 카드 시퀀스(블랙잭, 버스트, 페어 등)를 앱 전체 경로에서 재현해야 한다. |
| `getSnapshot`/`onState` | 화면 표시뿐 아니라 판 상태와 revision을 단언할 수 있어야 한다. |
| `dispatch` 명령 | 사용자 행동과 잘못된 명령의 결과를 검증할 수 있어야 한다. |
| 강제 종료 → 재기동 헬퍼 | 동일 `userData`로 복원 결과를 확인할 수 있어야 한다. |
| 저장 파일 사전 조작 | 테스트 프로세스가 재기동 전에 `app-session.json` 손상·미래 스키마 상태를 구성할 수 있어야 한다. |

Dock 등 테스트 앱의 공통 실행 정책은 [메인 E2E 설계](../../main/e2e-test-plan.md)를 따른다.

### 3.7 금액 입력·게임 오버 상세 검증

E2E-02와 E2E-15의 세부 수용 조건은 다음과 같다. 구현·통과 기록은 [E2E 구현 현황](e2e-implementation-status.md)과 [세션 보고서](../../session-reports/S10.5-inline-bet-input.md)에서 확인한다.

- 금액 숫자칸 클릭 → 같은 자리의 텍스트 필드로 전환 → `1`, `1.5`, `1.01`, `1.25` 입력 → Enter 확정 후 화면·`GameViewState`·재기동 저장값이 정확한 센트인지 확인한다. 현재 잔액 상한, $1.00 하한, Escape/필드 밖 클릭 취소, 딜 후 편집 거부를 검증한다.
- 편집 중에만 메인 창이 키보드 포커스를 받고, 확정·취소·숨김·접힘·클릭 통과·reload 뒤 `focusable:false`와 비집중 상태로 돌아오는지 확인한다. 220×150 DIP에서 베팅 행의 글자·버튼이 잘리지 않아야 한다.
- 빈 값·문자·음수·지수 표기·소수 셋째 자리·범위 밖 값은 명확한 오류를 표시하고 기존 베팅을 보존하며 딜하지 않는다. 반 센트 정산 대표값으로 $1.01 자연 블랙잭 반환금 $2.53과 서렌더 반환금 $0.51을 검증한다.
- 정산 결과 잔액 $1.00과 $0.99를 각각 만든다. $1.00에서는 다음 판·$1 딜을 허용하고, $0.99에서는 게임 오버 표시·다음 판 차단·새 게임 진입을 확인한다. 라운드 도중 잔액이 낮아져도 딜러 진행과 정산은 완료된다. 게임 오버 상태의 베팅·딜 거부는 코어 테스트에서도 확인한다.

## 5. 픽스처 설계

`fixtures/blackjack/*.json`에 카드 시퀀스를 둔다. 각 파일은 슈 순서(또는 다음 N장)와 시나리오 이름을 매핑한다.

- `player-blackjack.json`, `dealer-blackjack.json`, `both-blackjack.json`
- `standard-win.json`, `standard-loss.json`, `push.json`
- `insurance-hit.json`, `insurance-miss.json`
- `even-money-eligible.json`
- `double-eligible.json`
- `split-pair.json` (DAS 검증 포함), `split-ace.json` (재스플릿 금지 확인용)
- `late-surrender-eligible.json`
- `shoe-near-cut.json` (75% 소진 직전)
- `low-balance.json` (잔액 <$1 상태로 세션 직접 구성)
- $1.00 플레이 가능 경계·$0.99 게임 오버 경계와 $500을 넘는 잔액 전체 베팅은 격리된 저장 세션을 테스트 프로세스에서 구성한다. 픽스처 메타데이터만으로 잔액을 주입했다고 간주하지 않는다.

## 6. 범위 밖과 P0 보조 스위트

- 기존 오버레이 회귀와 E2E-21, 신규 APP 시나리오는 [메인 E2E 설계](../../main/e2e-test-plan.md)가 관리한다. 세션별 실행 순서는 [작업 세션 로드맵](../../work-session-roadmap.md)을 기준으로 한다.
- Playwright Electron으로 실제 외부 앱 포커스 이동, 물리 Alt+백틱 입력, 투명도 합성, 클릭 통과 대상 앱 반응, 물리 다중 모니터를 확인할 수 없으면 통과로 추정하지 않고 관련 이슈로 기록한다.
- 구 접근성 창·DPI·성능·서명 등의 일괄 제품화 세션은 폐기했다. 새로운 실제 요구에 따라 다시 선정한다.
- Windows 실 장비 검증 (GUI 동작은 실 장비에서 확인 — [빌드·배포 가이드](../../main/building-distribution.md) 참조).

## 7. 실행 원칙

- 테스트 파일은 `tests/e2e/*.spec.ts`에 둔다.
- E2E는 Forge 프로덕션 패키지를 대상으로 실제 Renderer 클릭부터 Main·저장·화면 반영까지 검증한다. 결정론적 슈와 격리된 `userData`를 사용한다.
- GUI가 필요한 Electron E2E를 CI 필수 게이트로 삼으려면 macOS·Windows 러너에서 실제 동작을 먼저 확인한다. 검증 범위와 실행 결과는 [E2E 구현 현황](e2e-implementation-status.md) 및 해당 [세션 보고서](../../session-reports/session-list.md)에 기록한다.
- 구현 순서와 남은 작업은 [작업 세션 로드맵](../../work-session-roadmap.md), 현재 파일·테스트 수와 알려진 한계는 [E2E 구현 현황](e2e-implementation-status.md)을 따른다.
