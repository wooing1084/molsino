# 바카라 E2E 설계

**목적:** 바카라의 실제 앱 연결과 공용 잔액·복구·UI 완료 조건을 정의한다.

**요약:** N04에서 패키지의 IPC·규칙·저장을, N05에서 UI 플레이와 두 게임 왕복을 검증한다. 아래는 새로 작성할 시나리오이며 현재 통과한 테스트가 아니다.

설계일: 2026-09-18. **테스트·픽스처 미구현**.

## 1. 실행 기준

프로덕션 Electron 패키지와 격리된 userData, 결정론적 8덱 슈를 사용한다. 저장은 실제 앱 저장소를 통과한다. N04의 API 호출 검증을 UI 클릭 검증으로 보고하지 않는다. 메뉴·공용 초기화·이관·IPC 신뢰는 [메인 APP 시나리오](../../main/e2e-test-plan.md)도 함께 확인한다.

BAC-07의 체크포인트는 실제 저장된 단계에서만 강제 종료한다. 존재하지 않는 일시적 상태를 테스트에 맞춰 생산 코드에 추가하지 않는다. 정상 종료와 강제 종료를 구분해 기록한다.

## 3. 하위 테스트와 기록

세 번째 카드 규칙표의 모든 경계, A/10/J/Q/K 점수, 8덱 고유성, 95% 이익의 나머지 49/50/51, 안전 정수 상한과 상태 검증은 하위 테스트로 보조한다. E2E에서 같은 조합을 전부 반복하지 않는다.

실제 실행 명령·통과/실패/스킵·장비·OS·미확인 범위는 완료 시 해당 N04/N05 보고서에 기록한다. 그때 바카라 구현 현황과 E2E 현황 문서를 추가한다. 현재는 계획만 있으며 앱 코드나 테스트를 완료한 것으로 표시하지 않는다.
