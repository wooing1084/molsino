# 바카라 제품 설계

**목적:** molsino에 추가할 바카라의 플레이 경험과 규칙을 정의한다.

**요약:** 공용 잔액으로 Player·Banker·Tie 중 한 곳에 베팅하는 기본 바카라를 제공한다. Banker 승리 수수료는 5%, Tie 순이익 배당은 8:1이며 최근 결과를 P·B·T 한 줄로 표시한다.

## 1. 상태와 범위

사용자가 확정한 범위는 기본 수수료 바카라, 한 판에 한 곳만 베팅, 최근 결과 P·B·T 한 줄이다. 노커미션 변형·페어 등 사이드 베팅·로드맵 형태의 기록판은 이번 범위에 포함하지 않는다. Player·Banker는 두 카드 패의 이름이며 사용자가 카드를 추가로 받을지 선택하지 않는다.

공용 잔액·메뉴·진행 중 이동 제한·$100 전체 새 시작은 [메인 제품 설계](../../main/product-design.md#5-메인-메뉴와-공용-잔액의-신규-설계)가 기준이다. 아래의 8덱·기록 20개·센트 반올림은 이 제품의 기본 설계값이며 실제 카지노의 모든 운영 절차를 복제한다는 뜻이 아니다.

## 2. 플레이 화면

같은 투명 창에서 공통 헤더·공용 잔액을 유지한다. 게임 영역에는 Player와 Banker의 카드·점수, 베팅 대상 세 버튼, 금액 입력·딜, 결과·다음 판, 최근 결과 한 줄을 둔다. P·B·T는 각각 Player·Banker·Tie임을 접근성 이름과 설명으로 구분한다.

- 베팅 전: 대상 하나를 선택하고 $1.00 이상 금액을 확정한 뒤 딜한다. 최초 대상은 Player, 최초 금액은 $1.00이다. 선택 표시는 흑백 테두리·문구로 구분한다.
- 진행 중: Main이 배분·추가 카드·정산을 자동 처리한다. 대상·금액·딜·메뉴를 비활성화한다. 숨김·복원은 허용한다.
- 결과: `Player 승 / Banker 승 / Tie`, 내 베팅 대상·금액, 순손익과 공용 잔액을 표시한다. Banker 승리 때 수수료가 반영된 반환금임을 알 수 있어야 한다.
- 다음 판: 같은 대상과 조정된 베팅 설정을 유지하되 사용자가 딜을 눌러야 시작한다. 자동 베팅·자동 재딜은 없다.
- 잔액 부족: 판 정산은 끝까지 진행하고, 공용 잔액이 $1 미만이면 새 딜을 막고 메뉴의 새 시작을 안내한다.

금액 직접 입력은 블랙잭과 같은 Enter 확정·Escape/필드 밖 클릭 취소·편집 중 임시 포커스를 사용한다. 입력 문자열의 십진 파싱 규칙은 기존 공통 파서를 활용한다. 베팅 대상 변경은 차감을 발생시키지 않는다.

220×150 DIP에서는 양쪽 패를 나란히 배치하고 카드·문구를 간결하게 표시한다. 베팅 버튼·금액 입력·메뉴의 클릭 영역은 24×24 DIP 이상, 글자는 11 DIP 이상을 지킨다. 최근 기록은 한 줄 안에서만 가로로 탐색하고 주요 조작을 밀어내지 않는다. 카드 연출이 Main의 정산이나 복구를 기다리게 하지 않는다.

## 3. 카드와 배분 규칙

카드 점수는 A=1, 2~9=표시 숫자, 10/J/Q/K=0이다. 패 점수는 합계의 일의 자리(합계 % 10)다. 높은 점수가 승리하며 같으면 Tie다. 최초 카드는 Player→Banker→Player→Banker 순으로 배분한다.

최초 두 장에서 어느 한쪽이라도 8 또는 9이면 내추럴로 양쪽 추가 배분을 끝낸다. 그렇지 않으면 Player는 0~5에서 세 번째 카드를 받고 6~7에서 멈춘다. Player가 추가 카드를 받지 않았다면 Banker도 0~5에서 받고 6~7에서 멈춘다.

Player가 세 번째 카드를 받았을 때 Banker의 최초 두 장 점수로 아래를 적용한다.

| Banker 점수 | 추가 카드를 받는 Player 세 번째 카드 점수 |
| --- | --- |
| 0~2 | 항상 |
| 3 | 8을 제외한 모든 값 |
| 4 | 2~7 |
| 5 | 4~7 |
| 6 | 6~7 |
| 7 | 받지 않음 |

한 패는 최대 세 장이다. 추가 배분 판단에 Player의 최종 합계를 세 번째 카드 점수 대신 사용하지 않는다. 규칙 근거는 [Massachusetts Gaming Commission Baccarat 규칙 §6·§9~12](https://massgaming.com/wp-content/uploads/RULES-Baccarat-4-11-2024.pdf)다.

## 4. 베팅과 정산

한 판에는 Player·Banker·Tie 중 정확히 하나의 베팅만 둔다. 최소 $1.00, 1센트 단위이며 사용 가능한 공용 잔액 이하만 허용한다. 내부 정수 연산이 안전한 범위를 넘는 금액은 딜 전에 거부한다. 베팅은 딜 확정 시 한 번 차감한다.

| 베팅과 결과 | 원금을 포함한 총 반환금 | 순손익 |
| --- | --- | --- |
| Player 베팅, Player 승 | 베팅액 × 2 | 베팅액 |
| Banker 베팅, Banker 승 | 원금 + 베팅액의 95%를 센트로 반올림 | 수수료 차감 후 이익 |
| Tie 베팅, Tie | 베팅액 × 9 | 베팅액 × 8 |
| Player 또는 Banker 베팅, Tie | 원금 | 0 |
| 그 밖의 패배 | 0 | −베팅액 |

기본 배당과 Banker 수수료는 [공식 Baccarat 규칙 §8·§13](https://massgaming.com/wp-content/uploads/RULES-Baccarat-4-11-2024.pdf)을 참고한다. 이 앱은 수수료 외상을 기록하지 않고 승리 즉시 차감한다. **95% 순이익을 가장 가까운 센트로 반올림하고 정확히 반 센트는 올림**하는 제품 정책을 사용한다. 예를 들어 $1.01 Banker 승리는 이익 $0.96, 총 반환 $1.97이며 $1.10 승리는 이익 $1.05, 총 반환 $2.15다. 수수료를 따로 반올림한 뒤 다시 차감해 이중 반올림하지 않는다.

정산·잔액·최근 기록은 함께 저장한다. 저장 재시도·재실행·화면 재생으로 지급과 기록이 반복되지 않는다.

## 5. 슈와 최근 기록

- 바카라 전용 8덱(416장)을 사용하며 블랙잭 슈와 섞지 않는다. Fisher–Yates와 Main의 난수 공급원을 사용한다.
- 새 슈에서 첫 카드와 그 값만큼 추가 카드를 버린다. 버림 계산만 A=1, 2~9=숫자, 10/J/Q/K=10을 쓴다. 버린 카드와 소비 인덱스는 내부에 보존하고 Renderer에는 공개하지 않는다.
- 컷 경계는 마지막 14장 앞(소비 인덱스 402)이다. 판 시작 때 경계 도달 또는 남은 카드 6장 미만이면 새 슈로 시작한다. 진행 중에는 셔플하지 않고 해당 판을 끝낸다. 경계를 지난 판 다음에 즉시 새 슈를 쓰는 것은 이 앱의 운영 정책이다.
- 메뉴 이동·다른 게임 플레이·재실행으로 슈를 새로 만들지 않는다.
- 최근 완료된 바카라 판 **20개**를 오래된 것부터 왼쪽에 `P B T …`로 표시한다. 결과는 내 베팅의 승패가 아닌 어느 패가 이겼는지다. Tie도 한 항목을 차지한다.
- 각 기록은 roundId로 중복을 막는다. 메뉴 이동·재실행·슈 교체에도 유지하고 전체 새 시작에서 지운다. 기록이 없는 경우 비어 있음을 표시한다. 통계·예측 문구는 넣지 않는다.

## 6. 완료 조건

메뉴에서 바카라를 선택해 세 대상의 베팅·승패·Tie 반환을 정확히 처리하고, 판 중 이동은 차단한다. 블랙잭과 같은 공용 잔액으로 돌아오며 정상·강제 종료 뒤 카드·금액·기록이 보존돼야 한다. 모든 구현·검증 범위는 [바카라 E2E 설계](e2e-test-plan.md)와 당시 세션 보고서에 기록한다.
