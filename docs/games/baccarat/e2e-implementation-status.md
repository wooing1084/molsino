# 바카라 E2E 구현 현황

**목적:** 바카라 시나리오의 실제 테스트 위치와 자동화가 확인하는 경계를 찾는다.

**요약:** 프로덕션 Electron 패키지와 격리된 userData를 사용하여 베팅·지급·저장 복구·게임 왕복·최소 크기를 확인한다. 규칙표와 잘못된 상태·금액 경계는 순수 코어 테스트가 보조한다.

## 실행 기반

- [`tests/e2e/baccarat.spec.ts`](../../../tests/e2e/baccarat.spec.ts)는 실제 `window.molsino` API와 UI를 사용한다. API 검사와 실제 클릭 검사를 구분한다.
- [`support/app.ts`](../../../tests/e2e/support/app.ts)가 임시 userData와 `baccaratFixture`를 전달한다. 픽스처는 테스트마다 임시 폴더에 작성하고 종료 시 정리한다.
- [`baccarat-shoe-source.ts`](../../../src/main/game/baccarat-shoe-source.ts)는 요청된 rank prefix에 나머지 실제 카드를 채워 유효한 416장 슈를 만든다. Main은 격리 테스트 환경에서만 픽스처를 읽는다. 첫 두 장 A/A는 테스트의 버림 카드다.
- [`tests/core/baccarat.test.ts`](../../../tests/core/baccarat.test.ts)는 Banker 세 번째 카드 표의 모든 셀, 내추럴·점수·반올림·안전 정수·불가능한 저장 상태를 검사한다.

## 시나리오별 구현

기대 동작의 기준은 [E2E 설계](e2e-test-plan.md)다.

| 시나리오 | 패키지 테스트가 확인하는 내용 |
| --- | --- |
| BAC-01~03 | 대상 버튼·금액 입력·딜·결과 클릭. P 승패, B $1.01/$1.10 배당과 수수료 문구, T 적중/패배 및 P/B Tie 반환. 파일 잔액·공개 결과와 대조 |
| BAC-04 | 내추럴과 양쪽 세 번째 카드 경로. 저장된 카드 순서·점수·결과 확인. 조건표 전체는 core 테스트 |
| BAC-05~06 | 선택 레벨 최소·최대와 잔액 제한·센트 입력, Escape/blur 취소. 복수 대상·내부 행동 위조·진행 중 변경 거부, 동일 ID·같은 revision 동시 딜의 한 번 적용 |
| BAC-07 | initial/playerThird/bankerThird/settle/settled 실제 저장 후 SIGKILL. 재기동 때 같은 카드·roundId·진행 잠금에서 재개하고 Banker 승리 배당·기록 1회 반영 |
| BAC-08 | 배분/정산 전 backup 파일 경로를 디렉터리로 만들어 실제 저장 실패. 마지막 파일 불변·이동 차단·UI 재시도·지급 1회·정상 재기동 보존. 결과 reload와 동일 명령 재전송도 검사 |
| BAC-09 | 새 슈 버림·소비 인덱스, 인덱스 401 시작 판에서 기존 슈 유지, 다음 딜에만 슈 교체, 메뉴 왕복에서 슈 보존 |
| BAC-10 | 22판 진행 후 최근 20개 순서·Tie, 재실행 유지, 전체 새 시작 시 제거 |
| BAC-11 / APP-08 | 블랙잭과 바카라 실제 메뉴 왕복·각 정산·공용 잔액·독립 슈. 잔액 감소 뒤 복귀 시 새 베팅액 조정, 과거 판 금액/결과 보존 |
| BAC-12 | 99센트 딜 차단, 100센트 딜 후 잔액 0이어도 정산 지속, 메뉴 새 시작에서 $100 복원 |
| BAC-13 | 최소·기본·최대 크기 버튼 24×24 이상·창 안 배치, 금액 입력 포커스 해제·흑백·불투명도·숨김 중 진행, 화면 PNG |
| BAC-14 | snapshot/push/응답의 슈·버림·미래 카드·내부 정산 정보 은닉, 다른 게임/이전 세션 명령 거부 |

컷 경계와 잔액 경계 일부는 앱을 종료한 뒤 격리된 유효 저장을 준비한다. 테스트용 공개 게임 우회 API를 추가하지 않는다. 강제 종료는 실제 저장된 단계에서 수행하며 순간적인 가상 단계를 만들지 않는다.

## 검증 경계

- 전체 Banker 조건표·배당 안전 정수·불가능한 상태는 core 검증이며 모든 조합을 UI 클릭으로 재현했다고 주장하지 않는다.
- 결과 저장 후 reload·재전송·재기동은 확인한다. IPC 응답 패킷 자체를 강제로 버리는 별도 전송 장애 주입은 하지 않는다.
- 금액 입력에서 Electron 창의 focusable 해제까지 자동화한다. 실제 외부 앱의 키보드 포커스 복귀·클릭 전달·물리 Alt+백틱·트레이·OS 합성은 별도 관찰 영역이다.
- PNG는 배치 확인용이다. 검정 글씨 결과 캡처에는 대비되는 배경을 테스트에서만 임시 적용한다. 이를 실제 데스크톱 투명 합성 검증으로 간주하지 않는다.
- 기존 블랙잭·앱 공통 회귀의 위치는 [블랙잭 E2E 현황](../blackjack/e2e-implementation-status.md)과 [메인 E2E 현황](../../main/e2e-implementation-status.md)을 따른다.

N04의 공통 레벨·한도·카드 공개 통합 사례는 [`gameplay-improvements.spec.ts`](../../../tests/e2e/gameplay-improvements.spec.ts)에 있다. 시나리오 목록은 [메인 E2E 설계](../../main/e2e-test-plan.md#4-n04-게임성-개선), 실행 결과와 미확인 범위는 [N04 보고서](../../session-reports/N04-gameplay-improvements.md)를 따른다.
