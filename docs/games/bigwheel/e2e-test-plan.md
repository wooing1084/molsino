# 빅휠 E2E 테스트 설계

**목적:** 프로덕션 Electron 패키지에서 빅휠의 사용자 흐름·정산·복구·표시 시점을 검증한다.

**요약:** `tests/e2e/bigwheel.spec.ts`에서 Main의 격리된 결정론적 칸 fixture를 사용한다. 순수 규칙과 저장 무결성의 상세 경계는 단위 테스트가 맡고, E2E는 화면 입력과 실제 저장 파일의 일치를 확인한다.

## 2. 실행과 한계

`npm run package` 이후 `npx playwright test tests/e2e/bigwheel.spec.ts`로 실제 패키지를 실행한다. launch helper의 `bigwheelFixture`는 `BIGWHEEL_TEST_SEGMENTS_FIXTURE` 경로를 전달하며 파일 형식은 `{ "indices": [0, 24] }`다. fixture는 격리된 E2E userData 환경에서만 Main이 소비한다. 당첨 배당 기대값은 구현 상수에서 계산하지 않고 공식 규칙의 고정값으로 검증한다.

공용 저장 형식과 메뉴 변경의 회귀는 `app-menu.spec.ts`, `baccarat.spec.ts`, `gameplay-improvements.spec.ts`를 함께 실행한다. 실제 명령·통과/실패 수·RED 증거·실행 환경은 [N05 세션 보고서](../../session-reports/N05-bigwheel.md)에 기록한다. 자동화한 Electron 활성화·숨김은 실제 운영체제 단축키나 다른 앱으로의 클릭 전달을 검증한 것으로 취급하지 않는다. Windows와 사람의 시각 판단이 필요한 투명 합성은 실제 관찰 범위를 별도로 기록한다.


## 3. 세 칸 확대 검증

2026-09-23 추가한 세 칸 표시 기준이다. `tests/e2e/bigwheel-zoom.spec.ts`가 BW-11~14를 검증하며, BW-01~10도 새 표시에서 회귀 검증한다. 실제 실행 결과는 [후속 보고서](../../session-reports/N05-bigwheel-result-zoom.md)를 따른다.

| ID | 시나리오 | 확인 기준 |
| --- | --- | --- |
| BW-11 | 세 칸 결과 일치 | 확정 i의 좌=(i+53)%54·중앙=i·우=(i+1)%54. 0/53 경계와 같은 심볼 연속, 조커/메가 구분, 중앙 이름·배당과 실제 정산 일치. 54개 전체 매핑은 하위 테스트로 보조 |
| BW-12 | 이동·감속·결과 공개 | 같은 방향으로 칸 경계가 이동하고 감속해 중앙 정렬. 빠른 결과도 조기 발표 없음, 늦은 결과도 임의 정지·역주행 없음. 결과/잔액/기록/달성 동시 공개, 동작 줄이기에서도 조기 결과 노출 없음 |
| BW-13 | 타임라인 수명과 복구 | 중복 snapshot·저장 오류/재시도·다음 판·숨김/reload·회전 중 리사이즈에서 중복 연출/추첨/지급 없음. 확정 결과 복원은 즉시 세 칸 정렬, 미정산은 진행 표시 |
| BW-14 | 최소창 가독성과 기존 조작 | 220×150·280×180, 흰색/검정에서 중앙 구역 이름·배당과 고정 포인터 직접 확인. 양옆 이웃 구분·최소24px 조작·전 구역 접근·Lv6 큰 금액/합계/한도 유지 |

BW-11 결과 검사는 최종 DOM 값뿐 아니라 포인터 중심과 중앙 칸 중심의 실제 위치를 비교한다. BW-12는 시작/진행/완료 시점의 이동 위치와 화면 캡처로 연출을 확인하고 텍스트 변경만으로 회전 통과를 판정하지 않는다. BW-14 캡처는 `app.browserWindow(page)`로 메인창을 선택하고 native bounds·Renderer viewport·paint를 기다린 뒤 수행한다.
