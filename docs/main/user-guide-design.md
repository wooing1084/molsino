# molsino 사용 설명서 작성 설계

**목적:** N07에서 앱 사용자가 읽을 Markdown 설명서를 바로 작성할 수 있도록 파일·독자·내용·검증 기준을 정의한다.

**요약:** 루트 [USER_GUIDE.md](../../USER_GUIDE.md) 한 파일에 한국어와 English 안내를 제공하고 README에서 연결한다. 실제 화면의 조작·세 게임의 한 판·저장과 문제 해결을 다룬다. 이 문서는 설명서 작성·갱신 기준이며 N07의 실제 검증은 [세션 보고서](../session-reports/N07-user-guide.md)에서 관리한다.

## 1. 산출물과 독자

- `USER_GUIDE.md`: 설치한 앱을 쓰는 사람을 위한 설명서. 제목 → 목적 → 요약 → 목차로 시작하고 한국어·English 절에 같은 핵심 동작을 안내한다. 단축키·메뉴 이름·게임 용어는 각 UI 언어의 실제 표시와 맞춘다.
- 루트 `README.md`: 다운로드·개발 실행의 시작 안내 역할을 유지하고 설명서 링크를 추가한다. 전체 조작법을 README와 설명서 양쪽에 반복하지 않는다.
- `docs/README.md`와 문서 작성 가이드: 설명서의 경로·역할을 연결한다. `AGENT.md`는 설계·문서 위치를 안내한다.

독자는 개발 도구를 설치하거나 소스를 수정하지 않고 게임을 플레이한다. macOS를 먼저 찾기 쉽게 안내하되 현재 Windows 앱의 메뉴 위치 차이도 짧게 설명한다. PDF·앱 내 도움말 창·새 네이티브 메뉴·웹사이트·필수 스크린샷 제작은 이 세션에 포함하지 않는다.

## 2. 설명서 내용

| 절 | 사용자가 알아야 할 내용 |
| --- | --- |
| 앱 소개·빠른 시작 | 로컬 싱글플레이 오버레이, 세 게임과 공용 잔액. `$`는 가상 게임 머니이며 구매·환전·현금 보상이 없음. 설치/실행은 README의 현행 경로로 연결하고 메뉴 선택 → 베팅 → 한 판 → 다음 판/메뉴 흐름을 먼저 보여 줌 |
| 창 조작 | 상단 드래그, 모서리 크기 조절과 메뉴 크기 프리셋, `◐` 클릭으로 흑백 전환, 같은 버튼에 마우스를 올려 불투명도 슬라이더 열기, `−` 숨김과 `×` 종료, macOS Option+백틱/Windows Alt+백틱 숨김·복원과 메뉴 대체 경로 |
| 클릭 통과·복원 | 클릭 통과는 창 전체에 적용되어 게임 버튼도 누를 수 없음. macOS 상태 아이콘/Windows 알림 영역의 실제 ‘보이기 / 클릭 통과 해제’ 메뉴로 복귀. 단축키 등록 충돌 때 메뉴 이용. 투명 픽셀의 자동 부분 통과나 창 위치 초기화 기능을 안내하지 않음 |
| 언어 | macOS 애플리케이션 메뉴/상태 아이콘과 Windows 알림 영역의 `언어 / Language`에서 한국어·English 선택. 확정한 선택의 재실행 보존. 첫 실행 언어는 작성 당시 실제 정책을 명시하고 N08 구현 때 갱신 |
| 잔액·레벨·베팅 | 최초/새 시작 $100, 세 게임이 같은 잔액 사용. 레벨의 입장 조건과 최소/최대 베팅, 자동 승급·강등 없음. 최고 달성과 현재 선택 구분. 금액 버튼에서 센트 단위 입력, Enter 확정·Escape/다른 곳 클릭 취소. 블랙잭 증감 버튼과 다른 게임의 직접 입력 차이 |
| 블랙잭 | 목표와 카드 점수, 베팅·딜·히트·스탠드·결과·다음 판. 더블·스플릿·서렌더·보험·이븐 머니의 짧은 뜻과 가능한 행동만 버튼으로 제공한다는 안내. 적용 규칙과 배당은 해당 제품 설계를 대조 |
| 바카라 | P(Player)·B(Banker)·T(Tie) 중 한 곳 선택, 금액·딜, 자동 카드 배분·결과·다음 판, Banker 수수료와 Tie 배당. 최근 결과는 기록이며 다음 결과의 보장이나 예측 기능이 아님 |
| 빅휠 | 여러 구역에 베팅 가능, 합계에 잔액·레벨 한도 적용, 0 입력/제거로 구역 취소, 회전 중 변경 불가, 당첨 구역과 원금 반환·순손익·최근 기록 읽기. 배당과 확률은 현행 제품 설계에 맞춰 설명 |
| 저장·이동·새 시작 | 판 중 메뉴 이동 불가, 숨겨도 진행 판을 취소하지 않음. 재실행 시 마지막 저장에서 복원. 잔액 $1 미만/현재 레벨 최소액 부족 시 메뉴에서 새 시작/하위 레벨 선택. 새 시작 확인은 잔액·레벨·판·기록을 초기화하고 언어는 유지 |
| 문제 해결 | 창 숨김·클릭 통과, 딜/메뉴 버튼 비활성, 금액 입력 취소/오류, 저장 재시도·백업 복구·새 게임 시작의 실제 선택지. 현재 자동 위치 보정·화면 장애 자동 복구를 제공한다고 쓰지 않고 필요하면 완전 종료 후 재실행을 안내 |

짧은 표와 순서 있는 절차를 사용한다. 모든 특수 규칙의 상세 표나 내부 구현을 옮기기보다 한 판을 끝내는 데 필요한 설명을 우선한다. 진행 중 잔액이 0이 되어도 정산이 끝나기 전에 새 시작하도록 안내하지 않는다. 초기화·복구의 데이터 변경 범위는 명확히 설명한다.

## 3. 기준 자료와 작성 원칙

- 창·언어·레벨·메뉴·공용 잔액: [메인 제품 설계](product-design.md), [구현 현황](implementation-status.md), `src/main/native-menu.ts`, `src/renderer/main.tsx`, `src/shared/i18n.ts`.
- 블랙잭: [제품 설계](../games/blackjack/product-design.md)와 `src/renderer/games/blackjack.tsx`.
- 바카라: [제품 설계](../games/baccarat/product-design.md)와 `src/renderer/games/baccarat.tsx`.
- 빅휠: [제품 설계](../games/bigwheel/product-design.md)와 `src/renderer/games/bigwheel.tsx`.
- 저장·시작 실패·복구: [메인 기술 설계](technical-design.md), 현재 Main·preferences 저장소와 복구 UI.

제품·기술 설계가 동작과 수치의 기준이며 설명서는 이를 사용자 언어로 전달한다. 설계만 있고 미구현인 N08 첫 실행 정책은 N07에서 이미 제공되는 동작으로 적지 않는다. 실제 코드와 문서가 다르면 현재 구현을 확인해 담당 현황에 남기고 설명서에 과장하지 않는다.

소스 명령, IPC, 저장 스키마, 테스트 픽스처와 Electron 설정은 사용자 절차에 넣지 않는다. 내부 접힘 상태처럼 조작 버튼이 없는 경로도 기능으로 소개하지 않는다. ‘항상 전체 화면 위에 표시’, ‘모든 모니터/OS 검증 완료’, ‘심사 승인 완료’ 같은 미확인 약속은 하지 않는다. 두 언어에서 돈·규칙·초기화와 오류의 의미를 일치시킨다.

## 4. 검증과 완료 조건

1. 실제 UI·메뉴 이름과 소스에 설명한 조작이 존재하는지 대조한다. 가능한 경우 현행 패키지로 창 복원·입력·한 판 흐름을 직접 확인하고 환경/미확인 항목을 N07 보고서에 기록한다.
2. 한국어·English 안내에서 창 복원, 클릭 통과 해제, 금액 확정/취소, 세 게임의 한 판, 잔액 부족·저장 실패·새 시작을 찾을 수 있는지 확인한다.
3. README → USER_GUIDE와 목차·상대 파일 링크·앵커, Markdown 표와 문서 구조를 확인한다. 설명서가 생성된 뒤에만 실제 파일 링크를 색인에 추가한다.
4. 문서만 바꿨다면 새 자동 테스트나 앱 전체 회귀를 작성·실행하지 않는다. 앱 동작까지 바꿀 필요가 생기면 이번 설명서 세션에 묵시적으로 포함하지 않고 변경 범위를 분명히 한다.

설명서와 진입 링크를 작성·검증하고 담당 문서·N07 보고서·세션 목록·PR을 완료한다. N08에서는 첫 실행 언어 문구를 실제 새 동작에 맞춰 후속 갱신한다. 기존 앱 테스트 통과 기록은 새 설명서 검증 결과로 재사용하지 않는다.
