## 1. 상태와 확인 사항

- 사용자가 말한 ‘투명 스크롤’은 카드 스크롤바가 아니라 흑백 버튼에 마우스를 올렸을 때 나오는 **투명도 조절 슬라이더 창**으로 확인했다.
- 사용자 요청은 두 게임의 하한·상한, 자본에 따른 레벨 선택과 성취도, 카드의 시간차 공개다. 현재는 설계만 진행한다.
- 레벨 선택은 사용자 추가 의견에 따라 기존 창 내부의 전용 페이지에서 좌우로 스크롤하는 카드 목록으로 설계한다. 확정된 레벨은 공통 상단에 항상 표시한다.
- 현재 잔액으로 입장 조건을 확인할지, 한 번 달성하면 영구 해금할지는 질문 중이다. 아래는 현재 잔액으로 입장하고 최고 달성 기록을 남기는 추천안이다.
- 시작 자금 $100과 기존 게임 규칙은 유지하는 전제로 제안한다. 레벨별 금액과 450ms 공개 간격은 플레이 검토 후 확정한다.

## 2. 투명도 조절창

### 현재 원인

`src/renderer/main.tsx`의 게임 창은 `--overlay-opacity`를 적용하지만 `OpacityPanel`은 동일 값을 스타일에 전달하지 않는다. `styles.css`의 `.opacity-popover`에는 독립적인 어두운 배경이 적용돼 있다.

### 제안 동작

- 게임 창과 조절창은 하나의 설정값을 사용한다. 조절창의 슬라이더·숫자·테두리·배경 전체에 같은 알파 배율을 한 번 적용한다. 개별 요소에 다시 곱하지 않는다.
- 기본 65%, 범위 20–100%, 5% 단위는 유지한다.
- 조절창을 열거나 드래그하는 동안 두 창 모두 설정값을 즉시 표시한다. 이때 조절창에 마우스가 있다는 이유로 100%가 되지 않는다.
- 조절창을 닫은 뒤 게임 창의 기존 호버 100%·마우스 이탈 후 0.8초 뒤 복귀를 유지한다.
- 창 간 이동·숨김·복원·작업 영역 경계 처리와 포커스 정책은 유지한다. 이번 항목에는 별도 색상 디자인 변경을 포함하지 않는다.

## 3. 테이블 레벨과 베팅 한도

### 실제 카지노 참고

2026-09-21 열람. 아래 조사표는 카지노가 보증한 현재 실시간 한도가 아니다. 조사일을 확인할 수 없어 금액대의 참고 사례로만 사용한다. 규칙 변형도 molsino와 다르다.

[Venetian 공식 안내](https://www.venetianlasvegas.com/resort/casino.html)는 현재 최소 베팅을 현장 테이블 표지에서 확인하도록 안내한다. [MGM 공식 블랙잭 안내](https://www.mgmresorts.com/en/gamesense/guide-to-blackjack.html)는 테이블별 최소·최대 베팅 한도를 설명한다.

실제 카지노의 금액대는 참고하되, 시작 자금 $100과 작은 싱글플레이 게임의 진행 속도에 맞춰 저액 방과 더 좁은 한도를 둔다. 자본 입장 조건과 레벨은 molsino의 게임 설계이며 실제 카지노의 규칙이라는 뜻이 아니다.

### 레벨표 제안

**사용자 결정: 레벨별 최소·최대 기본 베팅액은 모든 게임에 동일하게 적용한다.** 바카라 P/B/T도 같은 범위를 사용한다. 게임별 세부 조정은 후속 검토로 미루며 이번 구현 조건에 포함하지 않는다. 아래 금액 자체는 검토용 제안이며 모든 금액은 가상 달러다.

| 레벨 | 선택에 필요한 현재 잔액 | 최소 베팅 | 최대 기본 베팅 |
| --- | ---: | ---: | ---: |
| Lv.1 | $1 | $1 | $50 |
| Lv.2 | $500 | $5 | $250 |
| Lv.3 | $2,500 | $25 | $1,000 |
| Lv.4 | $10,000 | $100 | $5,000 |
| Lv.5 | $50,000 | $500 | $10,000 |
| Lv.6 | $100,000 | $1,000 | $25,000 |

새 시작은 Lv.1이다. Lv.1은 시작 자금 $100에서 손실이 나도 계속 플레이하도록 입장 조건을 $1로 둔다. Lv.6 이후에는 잔액이 증가해도 상한을 무한히 늘리지 않는다. 위 수치는 아직 확정되지 않은 게임 밸런스 제안이다.

### 레벨 선택과 달성 기록

- 메뉴에서 진행 중인 판과 저장 오류가 없을 때만 변경한다. 입장 조건은 레벨을 변경할 때 현재 잔액으로 검사한다.
- 이미 선택한 방은 최소 베팅을 낼 수 있는 동안 계속 이용한다. 예를 들어 $500으로 Lv.2에 들어와 $5를 잃어도 바로 퇴장시키지 않는다.
- 메뉴 열기·게임 전환·재시작은 선택한 방을 유지한다. 하위 방으로 이동했다가 상위 방으로 돌아갈 때는 현재 잔액을 다시 검사한다.
- 선택한 게임의 최소 베팅을 낼 수 없으면 다음 딜을 막고 ‘하위 레벨 선택’을 안내한다. 잔액 $1 미만일 때만 모든 방에서 플레이할 수 없다. 진행 중인 판은 끝까지 정산한다.
- 자동 승급·강등·증액은 하지 않는다. 사용자가 선택한 레벨과 최고 달성 레벨을 구분한다.
- 최고 달성 레벨은 정산 후 최고 잔액을 기준으로 기록하며 손실이 나도 지우지 않는다. 달성했다고 선택 레벨이 자동 변경되지는 않는다.
- 전체 새 시작은 $100·Lv.1·최고 잔액 $100으로 초기화한다. 기존 저장을 이전할 때는 현재 확정 잔액부터 기록하며 과거 최고 잔액을 추정하지 않는다.

### 베팅 제한

- 허용 금액은 선택 레벨의 공통 최소액 이상, ‘레벨 상한과 현재 사용 가능 잔액 중 작은 값’ 이하다. 센트 단위 입력은 유지한다.
- 상한 안에서는 연속 증액이 가능하다. 연패 횟수나 이전 증액을 이유로 금지하지 않는다. 마틴게일 전략 자체를 차단하는 기능이 아니다.
- 최대 $50인 방에서는 $1→$2→$4→$8→$16→$32 이후 $64를 걸 수 없다. 입장 가능한 상위 방으로 옮겨 증액할 수 있지만 마지막 레벨에도 고정 상한이 있다.
- 유한 자본에서 마틴게일이 승리를 보장하지는 않는다. 이번 변경은 테이블별 베팅 규모와 고정 상한을 만드는 것이며 카드 확률이나 승패를 조작하지 않는다.
- 직접 입력의 범위 초과는 오류를 표시한다. 다른 금액으로 몰래 확정하지 않는다. −/+는 경계에서 멈추며 증감 단위와 프리셋은 레벨에 맞춘다.
- 레벨 변경 시 다음 베팅만 새 범위로 조정하고 변경 금액을 보여 준다. 자동 딜하지 않으며 과거 결과와 진행 중 베팅을 변경하지 않는다.
- 블랙잭 상한은 최초 기본 베팅에 적용한다. 더블·스플릿·보험 추가금은 기존 규칙과 잔액 조건에 따라 허용하며 라운드 총 투입금이 기본 상한을 넘을 수 있다.
- 바카라 P/B/T 모두 선택 레벨의 같은 최소·최대 베팅액을 적용한다. Tie의 8배 순이익은 베팅액이 아닌 배당이므로 기존 규칙대로 지급한다.
- 레벨 변경으로 잔액·슈·기록을 초기화하지 않는다. Main에서도 레벨과 금액을 검증하며 Renderer가 임의로 정한 상한값을 신뢰하지 않는다.

## 4. 레벨 선택 화면

### 공통 상단의 현재 레벨

- 메뉴·게임 화면·레벨 선택 페이지의 공통 상단에 **확정된 현재 레벨**을 항상 표시한다. 예: `molsino · Lv.2`.
- 레벨 배지는 본문 스크롤이나 카드 탐색으로 사라지지 않는다. 선택 페이지에서 Lv.3을 구경해도 적용 전까지 상단은 Lv.2다.
- 상단은 현재 레벨만 간결하게 보여 준다. 최고 달성은 레벨 카드의 부가 정보로 구분하며, 레벨 공통 최소·최대 베팅액은 모든 게임의 베팅 영역 위에 항상 표시한다.
- 메뉴의 레벨 배지를 누르면 선택 페이지로 들어간다. 게임 중에는 읽기 전용으로 유지하고 기존 메뉴 경로로 돌아와 변경한다.
- 최소 크기에서 공간이 부족하면 앱 이름·게임명 표현을 줄이고 레벨과 필수 창 버튼은 유지한다. 작은 글씨로 억지로 압축하지 않는다.

### 게임 화면의 상시 한도 표시

- 블랙잭·바카라와 이후 추가되는 게임은 베팅 조작부 바로 위의 고정된 한 줄에 `최소 $5 · 최대 $250`처럼 선택 레벨의 공통 한도를 표시한다.
- 베팅 전·카드 공개 중·플레이어 판단·딜러 진행·결과·잔액 부족·저장 실패 등 게임 화면의 모든 상태에서 유지한다. 액션 버튼이나 오류 문구로 이 줄을 대체하지 않는다.
- 카드 영역을 스크롤해도 한도는 움직이지 않으며, 호버·툴팁·추가 클릭 없이 읽을 수 있어야 한다. 텍스트 편집 중에도 유지한다.
- 표시하는 최대액은 레벨의 상한이다. 잔액이 더 적다고 표기 자체를 낮추지 않는다. 실제 허용 베팅은 잔액과 상한 중 작은 값이고 현재 잔액은 별도 잔액 영역에서 확인한다.
- 현재 레벨과 한도는 같은 확정 상태에서 갱신한다. 레벨을 미리 보는 중이거나 저장에 실패했을 때는 새 한도를 적용된 것처럼 표시하지 않는다.
- 220×150에서도 한도 글자는 최소 11 DIP로 유지하고 잘라내거나 숨기지 않는다. 공간은 카드 본문과 여백에서 조정하며 긴 금액에는 불필요한 `.00`만 생략해 값을 정확히 표시한다.
- 아래 예시는 정보 배치도다. 두 게임 모두 같은 위치에 한도 줄을 둔다.

```text
molsino · Lv.2              ◐ − ×
‹ 메뉴                   $720.00
        카드 / 점수 영역
최소 $5 · 최대 $250
       베팅 / 행동 버튼
          상태 / 결과
```

### 좌우 카드 목록

같은 게임 창 안에 레벨마다 카드 한 장을 배치한 가로 목록을 둔다. 별도 창·팝업·텍스트 입력은 사용하지 않는다. 아래는 정보 구성 예시이며 220×150의 최종 픽셀 배치를 뜻하지 않는다.

```text
molsino · Lv.2              ◐ − ×
잔액 $720

     ┌──────────────────────┐
  ‹  │ Lv.3                 │  ›
     │ 최소 $25 · 최대 $1,000│
     │ 입장 조건      $2,500│
     │ $1,780 부족 · 잠김   │
     └──────────────────────┘
               3 / 6
[ 뒤로 ]               [ 적용 ]
```

- 카드에는 **레벨, 공통 최소/최대 베팅, 해금/입장 조건, 현재 선택·달성·자금 부족 상태**를 둔다. 한도는 한 번만 표시한다.
- 현재 정책 초안은 ‘현재 잔액으로 입장’이므로 구현 문구는 ‘입장 조건’이다. 영구 해금이 채택되면 ‘해금 조건’으로 바꾼다. 카드 UI 제안만으로 경제 정책이 확정된 것으로 보지 않는다.
- 처음 진입할 때 적용된 레벨 카드를 중앙에 보여 준다. 트랙패드 가로 스크롤·스와이프와 좌우 버튼으로 이동하고 카드 단위로 정렬한다. 첫/마지막에서는 멈추며 무한 순환하지 않는다.
- 일반 마우스도 좌우 버튼만으로 모든 카드에 접근할 수 있어야 한다. 드래그가 끝난 동작을 카드 선택 클릭으로 오인하지 않는다.
- 중앙 카드가 적용 후보지만 스크롤 자체는 레벨을 변경하지 않는다. 잠긴 카드도 볼 수 있고, 실제 변경은 ‘적용’으로만 수행한다.
- 상단의 적용된 레벨과 카드의 미리 보는 레벨은 구분한다. 같은 레벨은 ‘선택 중’, 가능한 다른 레벨은 ‘적용’, 자금 부족은 비활성 상태와 부족액으로 표시한다.
- 220×150에서는 카드 한 장 중심과 이웃 카드의 가장자리를 보여 주어 가로 탐색을 알린다. 글자는 최소 11 DIP·클릭 영역은 최소 24×24 DIP를 지킨다. 카드 본문만 탐색하고 헤더·잔액·뒤로/적용은 고정한다.
- 게임별 한도 표시 전환은 두지 않는다. 창을 확대하면 주변 카드와 부가 정보를 더 보여 주되 레벨별 공통 한도는 유지한다.
- 최고 달성·다음 목표·부족 금액은 카드 안의 부가 정보로 보여 준다. 핵심 한도·조건이 먼저 읽혀야 하며 더 긴 설명은 같은 페이지의 상세 보기로 제공한다.

### 적용과 상태 유지

- 페이지 진입은 게임 상태를 바꾸지 않는다. ‘뒤로’는 임시 탐색 상태를 버리고 메뉴로 돌아간다.
- 진행 중인 판·저장 오류가 없는 메뉴에서만 진입하고 변경한다. 카드 선택으로 게임을 자동 시작하지 않는다.
- 적용 성공 전에는 실제 레벨과 다음 베팅을 바꾸지 않는다. 성공 후 메뉴로 복귀하고 새 한도와 조정된 다음 베팅을 반영한다. 실패하면 같은 후보 저장을 재시도한다.
- 숨김은 페이지와 카드 탐색 위치를 유지한다. 재시작·Renderer reload는 확정된 레벨로 메뉴를 표시하며 저장 실패 복구는 일반 메뉴보다 우선한다.
- 마우스로 카드를 탐색할 때 외부 앱의 키보드 포커스를 가져오지 않는다.

## 5. 카드 공개 연출

### 순서와 속도

- 현재의 작은 숫자·문양을 유지한다. 공개 직전에는 같은 폭의 `?`를 보여 주고 숫자와 문양을 함께 약 140ms로 페이드 표시한다. 큰 카드 이미지·사운드·점멸은 추가하지 않는다.
- 첫 카드는 수신 후 바로 공개하고 이후는 **450ms 간격**, 마지막 카드에서 결과 표시는 **300ms 뒤**를 제안한다.
- 블랙잭 최초 배분은 ‘내 첫 카드→딜러 공개 카드→내 두 번째 카드→딜러 뒷면 배치’다. 딜러 비공개 카드의 값은 이때 수신·표시하지 않는다. 필요한 공개가 끝난 뒤 판단 버튼을 활성화한다.
- 히트·더블은 새 카드만 짧게 표시한다. 스플릿의 기존 카드는 위치만 옮기고 새로 받은 카드만 연출한다. 딜러는 비공개 카드 공개 후 추가 카드를 순서대로 보여 준다.
- 바카라는 P1→B1→P2→B2→필요하면 P3→필요하면 B3 순서다. 최초 네 장은 약 1.5초, 여섯 장이면 결과까지 약 2.6초를 목표로 한다. 저장·통신 대기 시간은 추가될 수 있다.

### 결과 미리 노출 방지

- 합계는 화면에서 공개된 카드만 반영한다. 최종 합계·승패·버스트·자연 블랙잭 결과를 먼저 보여 주지 않는다.
- 정산액·최종 잔액·이번 판 P/B/T 기록·새 레벨 달성도 마지막 카드 이후 결과와 같이 표시한다.
- 베팅과 추가 베팅 차감은 명령 성공 시 표시해도 된다. 정산이 먼저 끝났다면 연출 중 잔액 영역은 ‘정산 중…’으로 표시해 결과가 새지 않도록 한다.
- 툴팁·접근성 읽기에도 아직 보여 주지 않은 최종 합계와 결과를 노출하지 않는다.

### 저장·숨김·재시작

- Main의 저장과 정산은 Renderer의 연출 완료를 기다리지 않는다. 연출은 새로운 난수 생성이나 정산을 발생시키지 않는다.
- Renderer는 라운드 ID·동작/배분 순서·카드 ID로 공개 순서를 관리한다. 같은 상태 재송신·저장 중 알림·재구독으로 연출을 반복하지 않는다. 스플릿의 위치 이동도 새 카드로 취급하지 않는다.
- 자동 진행이 0ms여서 최종 상태가 먼저 도착해도 아직 표시하지 않은 카드 순서를 덮어쓰지 않는다. 공개 가능한 정보만으로 순서를 재구성할 수 있도록 공개 계약에 필요한 식별 정보를 추가한다.
- 연출 중에는 게임 판단·다음 판·메뉴 이동을 막아 화면과 실제 상태가 다른 시점의 명령을 보내지 않게 한다. 숨김과 종료는 허용한다.
- 저장 실패는 즉시 안내한다. 미저장 카드나 결과는 연출하지 않으며 저장 재시도로 중복 지급·중복 공개가 생기지 않게 한다.
- 숨김 복원·재시작·Renderer reload·화면 재진입에서는 과거 연출을 처음부터 반복하지 않고 현재 공개 가능한 최신 저장 상태를 표시한다. 숨겨진 동안 Main의 진행·저장은 계속된다.
- OS의 ‘동작 줄이기’에서는 페이드를 생략한다. 순차 공개 간격은 유지한다. 속도 선택 UI는 초기안에 넣지 않고 먼저 450ms로 실제 플레이를 확인한다.

## 6. 구현 경계와 검증

### 구현 대상

- `src/renderer/main.tsx`·`styles.css`: 조절창 알파, 레벨 선택 페이지, 잔액·결과 표시 시점.
- `src/renderer/games/blackjack.tsx`·`baccarat.tsx`: 베팅 범위, 카드 공개 순서, 합계와 버튼 제어.
- AppStore·공개 계약: 레벨 변경·베팅 검증·달성 기록·카드 공개 식별 정보.
- 레벨별 공통 한도를 한 곳에서 정의하고 Main이 최종 검증한다. 공개 상태에 확정 레벨과 한도를 함께 전달해 상단 레벨·상시 한도·실제 검증이 일치하게 한다.
- 현재 저장 형식은 엄격한 v2 스키마다. 필드를 임의로 추가하지 않고 v3 이전을 설계해 선택 레벨·최고 잔액·필요한 라운드 한도 정보를 저장한다.
- 기존 진행 판에 새 상한을 소급 적용하지 않는다. 카드·베팅·잔액·슈를 보존해 마친 뒤 다음 판부터 적용한다. 이전 후 기본 선택은 Lv.1이며 상위 레벨은 사용자가 고른다.
- 설계 확정 후 담당 제품·기술·E2E 문서에 반영하고 초안의 중복 내용을 정리한다. 현재 구현된 계약과 미구현 제안을 구분한다.

### 검증 조건

1. 20/65/100%·드래그·조절창 진입/이탈에서 양쪽 창의 알파와 포커스.
2. 두 게임의 최소·최대 정확한 경계, 1센트 초과/부족, 잔액 부족, 프리셋·직접 입력·IPC 검증.
3. 입장 자금 경계, 입장 후 손실, 최소액 부족, 진행 중 변경 거절, 변경 저장 실패, 재시작과 달성 기록 유지.
4. 상한 베팅의 블랙잭 더블·스플릿·보험 및 바카라 Tie 배당.
5. 카드별 공개 시점과 부분 합계, 비공개 카드 보호, 결과·잔액·기록의 선행 표시 방지.
6. 표시보다 빠른 상태 수신, 재송신, 스플릿, 자연 블랙잭, 저장 실패, 숨김 복원과 재시작.
7. 기존 저장의 진행 판과 큰 베팅을 보존하는 이전, 전체 새 시작 범위.
8. 최소 크기의 좌우 카드 탐색·끝 경계·스냅·마우스 버튼 대안, 고정된 현재 레벨·잔액·뒤로/적용 버튼. 미리보기 중 상단 레벨은 바뀌지 않으며 적용 성공 후에만 변경된다.

9. 두 게임의 모든 진행 상태·직접 입력·잔액 부족·저장 오류·본문 스크롤에서 최소/최대 한도가 항상 보이고 선택 레벨과 일치하는지 확인한다.

실제 프로덕션 패키지 E2E와 OS에서 관찰한 범위를 나누어 기록한다. 이번에는 게임 소스 수정·테스트 실행을 하지 않았다.
