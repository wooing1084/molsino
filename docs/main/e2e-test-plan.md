# 메인 기능 E2E 테스트 설계

**목적:** 앱의 오버레이·신뢰 경계와 신규 메인 메뉴·공용 잔액의 검증 기준을 정의한다.

**요약:** 기존 동작은 O·E2E-21 시나리오를 활용하고 새 공용 게임 기능은 APP 시나리오로 검증한다. 구 계획의 미진행 세션·일괄 완료 게이트는 폐기했다. 실제 테스트 범위는 구현 현황을 따른다.

## 1. 기존 동작의 회귀 기준

| ID | 동작 | 확인 기준 |
| --- | --- | --- |
| O-01 | 투명·흑백·불투명도 | 전경 20–100%, 밝은/어두운 배경에서 표시 |
| O-02 | 비활성 첫 클릭·복원 | 불필요한 포커스 이동 없이 마우스 동작 |
| O-03 | 금액 편집 | 명시적 편집 중 임시 포커스, 종료 후 비활성 복귀 |
| O-04 | 전체 클릭 통과 | 트레이 복구 경로 유지. 실제 아래 앱 전달은 OS 확인 |
| O-05 | 크기 조절·내부 접힘 | 창 크기·범위·상태 보존, UI 잘림 없음 |
| O-07 | Spaces·전체 화면 | 관찰한 OS 결과와 접근 가능한 복구 경로 기록 |
| O-08 | 재실행·중단 복원 | 중복 인스턴스·확정된 게임 상태 손실 없음 |
| O-09 | 정상 Renderer reload | Main의 게임 상태 유지·최신 공개 상태 동기화 |
| O-11 | Alt+백틱 | 숨김·비활성 복원 토글, 게임 상태 유지 |
| E2E-21 | IPC·Node 격리 | 비신뢰 sender·subframe·URL·payload 거부, raw Node 미노출 |

O-06 다중 모니터 확장, O-10 자동 부분 클릭 통과 실험, E2E-18 전체 창 설정 재실행 초기화의 구 계획은 폐기했다. 번호는 재사용하지 않는다. 이미 존재하는 관련 테스트는 제거하지 않지만 미구현 확장을 새 작업의 필수 게이트로 삼지 않는다. Renderer 장애 점검은 완료했으며 수정 세션은 계획에서 삭제했다. [점검 기록](../session-reports/N01-bug-review.md)은 보존한다.

위 표 전체를 별도 세션으로 다시 구현하거나 무조건 재검증하지 않는다. 공용 메뉴·게임 변경에 영향을 받는 기존 테스트를 사용하고 새로운 위험이 있는 경로를 보완한다. 실제 구현·미확인 OS 동작은 [E2E 현황](e2e-implementation-status.md)이 기준이다.

## 2. 메인 메뉴와 공용 잔액

**상태:** 아래 APP 시나리오 중 메인 메뉴·블랙잭 분리는 N02, 두 게임 왕복은 N03 범위다. 실제 구현/실행 여부는 E2E 현황과 세션 보고서를 따른다. 계약은 [메인 제품 설계](product-design.md#5-메인-메뉴와-공용-잔액의-신규-설계)·[기술 설계](technical-design.md#9-여러-게임과-공용-잔액의-신규-계약)를 따른다.

| ID | 시나리오 | 기대 결과 | 세션 |
| --- | --- | --- | --- |
| APP-01 | 기존 v1 블랙잭 세션을 새 형식으로 이관 | 잔액·센트 베팅·슈·보험/스플릿 등 판 상태·직전 명령 보존, $100 추가 지급 없음, 구 파일 불변 | N02 |
| APP-02 | 이관 중단·재실행·새 primary/backup 우선순위 | tmp 임의 승격 없음, 새 파일 존재 시 구 파일로 자동 후퇴 없음, 이관 중복 지급 없음 | N02 |
| APP-03 | 베팅·정산 저장 실패와 같은 후보 재시도 | 확정된 잔액·판 유지, 재드로우·중복 차감/지급 없음 | N02 |
| APP-04 | 메뉴→블랙잭→결과→메뉴 | 동일 공용 잔액, 게임별 슈·결과 유지. N03 이후 바카라 진입 허용 | N02 |
| APP-05 | 진행 중 이동·초기화 요청, 딜/메뉴 동시 명령 | UI와 Main 모두 금지, 허용된 한 순서만 적용, 다른 게임으로 명령 누출 없음 | N02 |
| APP-06 | 미완료 판 유무별 앱 재실행·Renderer reload | 앱 재시작은 미완료 게임 또는 메뉴, reload는 현재 화면. 자동 진행 1회 재개 | N02 |
| APP-07 | 메뉴 새 시작 취소/확정·응답 유실 | 취소 시 불변, 확정 시 $100·기본 설정·빈 판/기록·새 슈, 중복 초기화 없음 | N02 |
| APP-08 | 블랙잭↔바카라 왕복·각 정산·재실행 | 같은 공용 잔액, 각 슈 보존, 기존 베팅액이 잔액보다 클 때 새 베팅 조정 | N03 |
| APP-09 | 낮은 revision·역순 snapshot/push·같은 revision 저장 오류·이전 sessionId | 화면 역행 없음, 저장 오류 표시/해제, 이전 세션 명령 거부 | N02 |
| APP-10 | 새 API에 비신뢰 문서·조절창·잘못된 gameId/명령 호출 | 기존 신뢰 경계 유지, 슈·미공개 카드 미노출 | N02 |
| APP-11 | 금액 편집→메뉴, 최소 창 메뉴·게임, Alt+백틱 숨김·복원 | 초안 취소·비활성 복귀, 주요 조작 접근 가능, 진행 판 보존 | N02 |
| APP-12 | 손상·미래 버전 새 저장, 기존 형식 손상, 신규 저장 경로 오류 | 원본 보존·명시적 복구, 공용 잔액 추정/자동 초기화 없음 | N02 |
| APP-13 | 잔액 $1.00/$0.99와 새 시작 | $1이면 딜, $0.99이면 베팅 차단·메뉴 이동·$100 새 시작. 진행 중에는 정산 지속 | N02 |

베팅 차감·진행 중 게임 잠금·정산 지급·잠금 해제를 실제 저장 파일에서도 확인한다. 공용 잔액과 게임 상태를 서로 다른 순간의 값으로 검사하지 않는다. APP-01은 결과 상태만이 아니라 미완료 판을 이관해야 한다.

## 3. 실행과 판정

기능 완료는 프로덕션 패키지의 실제 앱 경로에서 검증한다. 명령·정책은 [로드맵](../work-session-roadmap.md#검증-정책), 현재 스위트는 [메인 E2E 현황](e2e-implementation-status.md)에 있다. 추가된 테스트의 실행 결과와 한계는 해당 세션 보고서에 기록한다.

자동화만으로 실제 아래 앱 클릭·스크롤, 업무 앱 포커스 복귀, 투명 합성, 물리 단축키·트레이 조작을 통과 처리하지 않는다. 관찰한 OS·장비와 결과만 기록하고 미확인 범위를 새로운 필수 개발 세션으로 자동 전환하지 않는다.
