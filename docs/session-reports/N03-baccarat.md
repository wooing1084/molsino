# N03 — 바카라 구현

**목적:** 메뉴에서 기본 수수료 바카라를 선택하고 블랙잭과 공용 잔액으로 플레이하도록 연결한다.

**요약:** 독립된 바카라 코어·슈·저장 검증과 실제 플레이 화면을 구현했다. 단계별 원자 저장·자동 진행·최근 20개 기록을 연결하고, 승리 배당의 중복 방지·강제 종료 복구·두 게임 왕복을 패키지 E2E로 확인했다.

## 1. 구현과 결정

- 8덱·버림·컷 경계·내추럴·Player/Banker 세 번째 카드 규칙을 순수 TypeScript 코어로 구현했다. 블랙잭의 6덱 규칙과 독립적이다.
- P/B/T 한 곳에 정수 센트로 베팅한다. Banker 승리의 95% 이익은 반 센트 올림하고 Tie 순이익은 8배다. 차감 전에 최대 반환·최종 지갑·중간 곱의 안전 정수 범위를 검사한다.
- AppStore가 공용 잔액과 배분 단계를 함께 저장하고 성공한 단계에서만 자동 진행을 예약한다. 저장 실패는 같은 후보를 유지한다. 진행 중 게임 잠금·메뉴·전체 초기화·기존 저장 이전 정책을 재사용한다.
- v2 게임 상태 검증에서 실제 슈 prefix로 현재 판을 재생하여 카드·소비 위치·세 번째 카드 규칙을 확인한다. 최신 정산 키·roundId·단계·기록 순번이 일치해야 한다.
- 최근 20개 기록은 표시용이며 전체 정산 원장을 대신하지 않는다. 현재 판의 정산 증거와 명령 ID/revision, 완료 판 순번으로 중복 지급을 막는다. 내부 순번과 정산 키는 Renderer에 노출하지 않는다.
- 메뉴의 바카라를 활성화하고 카드·대상·금액 입력·딜·결과·반환금·수수료·최근 결과 UI를 추가했다. 인라인 입력은 기존 십진 파서와 임시 포커스 정책을 사용한다.
- Banker 곱의 나머지는 5의 배수만 가능하므로 설계의 반올림 경계 예시를 실제 가능한 45/50/55로 명확히 했다.

파일별 책임과 현재 동작은 [바카라 구현 현황](../games/baccarat/implementation-status.md), 상태·저장 계약은 [기술 설계](../games/baccarat/technical-design.md), 시나리오별 위치는 [E2E 현황](../games/baccarat/e2e-implementation-status.md)을 따른다.

2026-09-18 사용자 요청으로 WIP 커밋 `0798ff6`에서 중단했다가 09-21에 재개했다. 재개 시 원격 DEV에도 해당 커밋이 반영되어 있었다. 후속 변경은 승리 배당 복구·컷 경계·베팅 조정 검증, N02 IPC 테스트의 기대값 갱신과 문서 마무리다. 임시 인수인계 문서는 사용자의 요청에 따라 삭제하고 필요한 기록을 이 보고서로 옮겼다.

현재 바카라 E2E 24개는 P/B/T 배당, $1.01/$1.10 수수료, 각 저장 단계의 SIGKILL·재기동, 배분/정산 저장 실패·재시도, 최근 20개·전체 초기화, 비공개 상태 은닉, 두 게임 공용 잔액·독립 슈, $0.99/$1 경계, 최소·기본·최대 크기와 입력/숨김을 확인했다. 컷 인덱스 401에서 시작한 판의 기존 슈 유지와 다음 딜의 새 슈, 다른 게임에서 잔액이 감소한 뒤 새 베팅만 조정되는 경로도 추가했다. 복구·재시도 시 Banker 승리 $1의 반환 $1.95가 한 번 반영돼 최종 잔액이 $100.95임을 확인한다.

기존 49개 회귀는 v1 보험/스플릿 이전·원본 보존, 저장/백업 복구·실패 재시도, 블랙잭 금액·정산·재실행, IPC 신뢰·구독·Node 격리와 오버레이를 포함한다. APP-10은 유효해진 바카라 deal을 스키마 오류로 기대한 테스트였다. 내부 advanceBaccarat는 스키마에서 거부하고, 다른 게임 화면의 유효한 deal은 INVALID_ACTION으로 거부하도록 분리했다. 제품 동작을 바꿔 테스트를 통과시키지 않았다.

초기 재개 검사에서는 캡처용 스타일 제거 코드의 Node 타입 오류가 발견되어 parentNode.removeChild로 수정한 뒤 타입 검사를 통과했다. 전체 E2E를 통과한 것처럼 초기 실패를 생략하지 않으며, 실패한 항목만 수정 후 재실행했다.

## 3. 미확인 범위와 다음 작업

- Windows GUI, 실제 외부 앱 포커스 복귀·클릭 전달, 물리 Alt+백틱·트레이·OS 투명 합성은 이번에 검증하지 않았다. 창 상태·DOM·PNG 관찰과 구분한다.
- 결과 reload·명령 재전송·재기동은 확인했으나 IPC 응답 패킷 자체를 버리는 전송 장애 주입은 하지 않았다.
- 기존 블랙잭의 모든 규칙 조합을 새로 확장하지 않았고, N01의 Renderer 장애 복원·극단 금액 결함 전체를 수정한 세션도 아니다.
- 다음은 **N04 사용성 개선**이다. 실제 사용에서 발견한 불편과 영향도를 기준으로 사용자가 개선 항목을 선정한다. 폐기한 구 백로그는 자동 복원하지 않는다.
