# 세션 보고서 운영 방침

**목적:** `docs/session-reports/`에 세션 결과를 기록하고 목록을 유지하는 방법을 정한다.

**요약:** 각 세션 종료 시 보고서를 작성하고, 보고서 첫머리에 세션 요약을 둔 뒤 [세션 목록](session-list.md)에 ID별 한 줄을 추가한다. 검증 결과와 미확인 범위는 해당 보고서에서 관리한다.

## 보고서 작성

각 세션이 끝나면 기능 세션은 `N<두 자리 번호>-주제.md`(예: `N01-critical-bug-review.md`), 설계 세션은 `D<두 자리 번호>-주제.md` 형식의 정리 문서를 작성한다. 세션의 목적·주요 결과를 최상단에 간결히 요약하고, 이어 목차를 둔다. 목차 뒤에는 완료 여부와 날짜를 표시한다. 본문에는 실제 작업 범위, 주요 변경과 결정, 검증 명령·환경·통과/실패/스킵 수, 미해결 이슈와 다음 시작점을 기록한다.

기존 `SNN` 보고서의 ID와 당시 결과는 유지한다. 2026-09-18 이전 미진행 일정은 폐기됐으며 현재 순서는 로드맵을 따른다.

여러 세션을 한 번에 수행했다면 하나의 묶음 보고서를 사용할 수 있다. 이 경우 보고서에 포함된 세션 ID와 각 범위를 명확히 적는다. 기존 보고서가 가리키는 당시 사실은 보존하고, 뒤에 바뀐 결정은 날짜를 밝힌 후속 주석과 현재 기준 문서 링크로 구분한다.

## 세션 목록 갱신

보고서를 작성한 뒤 [session-list.md](session-list.md)에 **세션 ID마다** 한 줄의 아주 짧은 설명과 보고서 링크를 추가한다. 묶음 보고서라면 여러 ID가 같은 보고서를 가리킬 수 있다. 같은 세션의 후속 보고서가 있으면 해당 ID의 한 항목에서 둘 다 연결한다. 목록에는 상세 구현이나 검증 수치를 복제하지 않는다.

## 기록의 역할

보고서는 해당 세션에서 실제로 수행한 작업과 검증의 이력이다. 현재 메인 기능·블랙잭의 제품·기술 계약은 [문서 안내](../README.md)의 각 기준 문서를, 다음 작업 순서는 [로드맵](../work-session-roadmap.md)을 따른다. 이전 검증 기록은 후속 작업자가 이미 통과한 범위와 여전히 확인하지 않은 범위를 구분하는 데 사용한다. 세션에 속하지 않은 통합 검증의 위치는 [문서 작성 가이드](../documentation-guide.md#검증-기록)를 따른다.
