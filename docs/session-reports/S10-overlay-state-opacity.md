## 범위와 계약

- 창 표시 상태는 Main이 소유한다. `expanded | collapsed | hidden` 중 하나이며 숨기기 전의 펼침/접힘 모드를 기억한다. 접힘은 정확히 140×30 DIP이고, 펼치면 접기 직전의 펼친 bounds로 돌아간다. 같은 전환을 반복해도 크기를 덮어쓰지 않는다.
- 접힘·숨김은 진행 중 판을 지우지 않는다. 창 표시 상태와 무관하게 Main의 딜러 자동 진행과 단계별 저장은 계속되며, 펼침·복원 시 최신 committedState를 보여 준다. 앱 재실행 후 저장된 `dealerTurn`도 자동으로 이어간다. 사용자 요청에 따라 일시정지 상태는 두지 않는다.
- 불투명도는 펼친 창 우측 상단 색상 전환 버튼에 호버하면 나타나는 별도 작은 조절창의 슬라이더로 20–100%(5% 단위, 기본 65%) 조절한다. 값은 전경 CSS opacity에만 적용한다. 조절창은 버튼 좌우의 현재 작업 영역 여유를 보고 열리는 방향을 바꾸며 최종 bounds를 화면 안에 보정한다. 버튼→조절창 이동 중 유지하고 둘 다 벗어나면 닫는다. 슬라이더 조작 중에는 즉시 미리 보고, 일반 호버는 100%, 이탈 0.8초 후 선택값으로 돌아간다.
- 접힘/펼침과 Renderer reload 동안 실행 중 불투명도를 유지한다. 앱 재실행 시 창 설정은 기본값으로 초기화하며 게임 세션만 복원한다. `preferences.json`은 만들지 않는다.
- Preload는 타입·런타임 검증된 창 상태 조회/명령만 노출한다. 리사이즈 token은 접힘·숨김·프리셋 전환에서 만료되고, 접힌 상태에서 리사이즈를 시작할 수 없다.
- 후속 사용자 피드백: 헤더의 `▁`는 일시정지가 아니라 접기 버튼이었다. 버튼은 제거하고 내부 접힘 상태·IPC는 유지한다. Alt+백틱은 창 숨기기 전용 전역 단축키이며, 숨김 중 재입력해도 복원하지 않는다. `−` 버튼과 같은 숨김 경로를 쓰고 복원은 트레이에서 한다. 단축키 점유 시 등록 실패를 경고로 처리하고 정상 동작을 유지하며 종료 시 등록을 해제한다.

## E2E 선작성 계획

1. 창을 접어 140×30 DIP와 간략 UI를 확인하고 펼쳐 사용자 크기로 돌아오는지 검증한다. 반복 명령과 접힌 상태 리사이즈 거부도 포함한다.
2. 플레이어 진행 중 판을 접었다 펼쳐 카드·revision·잔액이 보존되는지 검증한다. 딜러 차례에서 숨기거나 접어도 결과까지 진행하는지 확인한다.
3. 색상 버튼 호버 조절창의 불투명도 슬라이더 20/100% 경계·마우스 조작, 접힘·Renderer reload 중 유지, 재실행 시 65% 초기화와 게임 세션 복원을 검증한다.
4. 화면 좌우 가장자리에서 조절창이 반대쪽으로 열리고 workArea를 벗어나지 않으며, 버튼에서 조절창으로 마우스를 옮길 때 유지·이탈 시 닫힘을 검증한다. 조절창 문서의 게임·창 명령은 거부한다.
5. 헤더 접기 버튼이 보이지 않고, 패키지의 전역 Alt+백틱이 등록되며 숨김 상태에서 재숨김해도 복원하지 않고 Main 복원 경로는 작동하는지 확인한다. 물리 키 입력·실제 Tray 클릭은 수동 OS 검증으로 남긴다.

## 검증 결과

- 선작성 red: 프로덕션 패키지 E2E에서 `접기` 버튼이 없어 S10-01·02가 기대한 이유로 실패했다. 남은 선작성 테스트는 red 확인 뒤 중단했다.
- 첫 구현 E2E 3/4: 불투명도 값 표시를 `output`으로 추가하면서 기존 베팅 테스트의 단일 `output` 선택자와 충돌했다. 값 표시를 `span`으로 바꿔 기존 베팅 계약을 유지했다.
- 초기 구현의 딜러 활성 플래그가 독립 GameStore의 단위 테스트 2건을 깨뜨려 보완한 적이 있으나, 사용자 요청으로 일시정지 기능 자체를 제거했다. 최종 `npm run check`는 11파일 108/108 통과했다.
- 사용자 추가 요구의 선작성 red: S10-06에서 색상 버튼 호버 뒤 조절창 BrowserWindow가 없어 기대한 이유로 실패했다.
- 일시정지 제거의 선작성 red: S10-04·05에서 숨김·접힘 중 저장 상태가 `dealerTurn`에 머물러 기대한 이유로 2/2 실패했다. 예약 취소 경로를 제거한 뒤 두 테스트 모두 통과했다.
- 사용자 후속 요구의 선작성 red: S10-09에서 헤더 `접기` 버튼이 남아 있어 기대한 이유로 실패했다. 단축키 단위 테스트도 구현 모듈 부재로 red였다.
- 공식 완료 검증: `npm run test:e2e` — macOS arm64, Electron 44.3.0, Forge 프로덕션 패키지, 전체 25/25 통과(S10 9건), 실패/스킵 0. `npm run check` — 12파일 110/110 통과. 불투명도 조절창은 메인 창 최소 레이아웃을 차지하지 않는다.

## 변경사항

- `src/main/main.ts`, `src/main/windows/hide-shortcut.ts`: Main 소유 창 상태 revision, 접힘·펼침·숨김 전이, 펼친 bounds와 숨기기 전 모드 보존, 140×30 DIP 전용 크기 경로, 접힌 상태 리사이즈 거부. 색상 버튼 호버의 작은 자식 BrowserWindow, workArea 기반 좌우 배치·위아래 clamp·호버 수명, 불투명도 IPC와 메인/팝업별 신뢰 검증. 전역 Alt+백틱 등록·등록 실패 경고·종료 시 해제, 콜백은 기존 hide 경로만 호출.
- `src/main/game/game-store.ts`: 딜러 내부 명령은 창 표시 상태와 무관하게 한 단계씩 예약한다. 중복 예약은 막고, 재실행 시 저장된 `dealerTurn`을 이어간다. 일시정지 플래그와 예약 취소 경로는 없다.
- `src/shared/contracts.ts`, `src/preload/preload.ts`: strict 20–100%·5% 단위 스키마, 공개 창 상태 조회/구독, 제한된 불투명도 API.
- `src/renderer/main.tsx`, `src/renderer/styles.css`: 간략 접힘 바와 펼치기 버튼은 내부 상태에 남기되 헤더의 `▁` 버튼 제거. 색상 전환 버튼 호버 트리거·팝업 슬라이더·값 표시, 220×150 최소 레이아웃.
- `tests/e2e/overlay-state.spec.ts`: S10 9건. S10-04·05는 숨김·접힘 중에도 딜러가 결과까지 진행함을 검증하고, S10-09는 접기 버튼 부재·단축키 등록·재숨김의 멱등성·복원 경로를 확인한다. `tests/main/hide-shortcut.test.ts`는 등록 콜백·실패·해제를 검증한다. 기존 `ipc-state.spec.ts`는 새 API 경계에 맞춰 회귀를 확장했다.

## 관련 이슈와 다음 시작점

- E2E는 BrowserWindow 크기·CSS opacity·게임 상태와 IPC 경계·전역 단축키 등록을 확인한다. 물리 Alt+백틱 입력 자체, 실제 macOS/Windows 데스크톱 합성 투명도, 외부 앱 포커스, Tray 메뉴의 OS 동작과 Windows 실장비 동작은 확인하지 못했다. 해당 조건을 통과로 추정하지 않는다.
- S10은 불투명도·접힘의 재실행 기본값만 검증했다. 위치·크기·색상·클릭 통과까지 포함한 전체 창 설정 초기화(E2E-18)와 모니터 변화 대응은 S11 범위다.
- 다음 시작점: S11 위치·다중 모니터와 시작 기본값. 현재 화면의 workArea/음수 좌표 보정 설계를 확정하고 E2E를 먼저 작성한다. 게임 세션은 계속 복원하되 `preferences.json`은 만들지 않는다.
