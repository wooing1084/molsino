# N02 — 메인 메뉴와 블랙잭 분리

**목적:** 블랙잭 전용 앱을 메인 메뉴·공용 상태/저장과 블랙잭 게임 영역으로 분리한다.

**요약:** 메뉴, 앱 단일 작성자와 v2 저장, 기존 블랙잭 데이터 이전, 앱 API와 별도 블랙잭 화면을 구현했다. 바카라는 준비 중으로 유지하고 N03으로 분리했다.

## 1. 범위와 구현

사용자 요청으로 N02를 메인 메뉴·공용 기반·블랙잭 분리에 한정했다. 구현 전에 저장 이전 → 앱 명령·메뉴 → 화면 분리의 책임과 실패 조건을 검토했다. 기준은 [메인 기술 설계 §9](../main/technical-design.md#9-여러-게임과-공용-잔액의-신규-계약)와 [현재 로드맵](../work-session-roadmap.md)이다.

- `AppStore`가 공용 wallet·화면·진행 판 잠금·revision과 저장 후보를 소유한다. `blackjack-adapter`가 기존 순수 엔진에 잔액을 주입하고 결과를 추출한다.
- `AppSessionRepository`가 v2 스키마와 v1 이전을, 공유 `AtomicSessionRepository`가 primary/backup·sync·rename·복구 원본 보존을 맡는다. 잔액은 wallet에 한 번만 저장하며 기존 파일은 그대로 남긴다.
- `window.molsino`는 sessionId/commandId/expectedRevision envelope와 앱 snapshot을 제공한다. 블랙잭 공개 정보는 `AppView.blackjack`으로 분리하고 창 API는 OverlayAPI로 묶었다. durable revision과 공개 이벤트 순서 viewSequence를 구분한다.
- Renderer의 앱 셸은 메뉴·잔액·복구·초기화 확인·창을, `BlackjackGame`은 카드·베팅 입력·행동·결과를 담당한다.
- 진행 중·저장 중·저장 실패 때 메뉴 이동과 초기화를 막는다. 앱 재시작은 미완료 판 또는 메뉴, Renderer reload는 현재 화면을 복원한다.
- I/O로 시작·이관이 실패하면 초기화 대신 불러오기 재시도를 제공한다. 게임 전이 오류와 실제 저장 실패를 구분한다. 미확정 저장이 있는 종료에는 손실 범위를 확인한다.
- 전체 새 시작은 메뉴에서 취소/확정한다. 실패 후 재시도 성공 시 확인 화면도 닫는다. 바카라 규칙·화면·슈는 이번 변경에 포함하지 않았다.

## 2. 검증

환경: macOS 26.4.1 arm64, Node 22.22.1, Electron 44.3.0. 격리된 임시 userData와 프로덕션 패키지를 사용했으며 실제 사용자 저장 파일을 변경하지 않았다.

| 검증 | 결과 |
| --- | --- |
| 선작성 메뉴 E2E | 기존 패키지에서 바카라/게임 선택 메뉴 요소 부재로 실패 확인 |
| `npm run check` | 앱·E2E 타입 검사와 하위 테스트 15파일 135개 통과 |
| `npm run package` | 로컬 Electron ZIP을 지정한 macOS arm64 패키징 성공 |
| `npx playwright test --timeout=20000` | 49개 중 47개 통과. 응답을 앱/블랙잭으로 분리한 뒤 남은 오버레이 assertion 2개를 수정하고 해당 2개 재실행 통과. 최종 49개 모두 검증, 스킵 없음 |
| `npm run smoke` | 메뉴·블랙잭 딜·AppStore·IPC·Node 격리 통과 |
| 최소 크기 화면 | 220×150 메뉴·초기화 취소/확정·블랙잭 화면 PNG를 시각 확인 |
| 문서 | 담당 설계·구현/E2E 현황·로드맵·세션 목록 갱신과 상대 링크 확인 |

E2E 확인 범위는 보험 결정/스플릿 판의 v1 이전과 구 파일 불변, 반복 실행, 새 backup 우선 복구, 시작 I/O 재시도, 실제 베팅/딜러 정산/초기화 저장 실패와 동일 후보 재시도, 메뉴·딜 경합, 진행 중 이동 차단, 초기화 재전송·이전 세션 거부, 최소 화면·입력 초안 취소다. 기존 블랙잭 베팅·센트 정산·정상/강제 종료·컷 경계, IPC 신뢰·비공개 카드 은닉, 창 크기·불투명도·숨김/접힘·Dock 회귀도 실행했다.

마지막 오버레이 재검증 명령은 `npx playwright test tests/e2e/overlay-state.spec.ts --grep '딜러가 계속' --timeout=20000`이며 2/2 통과했다.

초기 회귀 실행에서 구 v1 파일 구조·실행 즉시 블랙잭 화면을 가정한 assertion과 메뉴 진입 저장 완료 전에 파일을 읽는 테스트 경합을 발견하여 현재 계약에 맞췄다. 별도 저장 오류 테스트에서는 후보를 실제 디스크에 다시 쓰고 결과와 금액이 한 번만 반영되는 것을 확인했다.

## 3. 한계와 다음 작업

- Windows GUI, 실제 외부 앱 포커스 복귀·클릭 통과, 물리 Alt+백틱·트레이·OS 투명 합성은 이번에 검증하지 않았다. 자동화의 창 상태 관찰과 구분한다.
- N01의 강제 Renderer 장애 복원과 극단 금액 결함 전체를 수정한 세션이 아니다. 앱 작성자는 후보 없는 내부 오류를 저장 재시도로 오인하지 않지만 기존 블랙잭 산술 상한 정책을 재설계하지 않았다.
- 기존 블랙잭의 모든 규칙 조합·모든 저장 체크포인트를 새로 확장하지 않았다. 바카라와 APP-08 두 게임 왕복은 미구현이다.
- 다음 작업은 **N03 바카라 구현**이다. 이번에 분리한 앱 기반에 바카라 규칙·저장·화면을 연결하고 두 게임 공용 잔액을 검증한다.
