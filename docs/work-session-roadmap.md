## 1. 세션 운영 원칙

모든 기능 세션은 아래 순서를 지킨다.

1. **작업 내용 선정** — 한 세션에서 완료할 사용자 가치와 범위를 고정한다.
2. **브랜치 생성** — 최신 `DEV` 브랜치에서 해당 작업의 feature 브랜치를 분기한다.
3. **설계** — 계약, 상태 전이, 실패 처리, 완료 조건을 먼저 문서화한다.
4. **E2E 작성** — 구현 전 기대 동작을 테스트로 작성하고 의도한 이유로 실패하는지 확인한다.
5. **개발** — E2E와 하위 계층 테스트를 통과시키는 최소 구현을 완성한다.
6. **E2E 검증** — 프로덕션 번들을 대상으로 E2E만 실행하고 결과를 기록한다.
7. **문서 정리 및 최신화** — [문서 작성 가이드](documentation-guide.md)에 따라 세션 결과와 관련 기준 문서를 갱신한다.
8. **커밋 및 push** — 완료한 코드·테스트·문서를 feature 브랜치에 커밋하고 원격에 push한다.
9. **PR 생성** — `DEV`를 대상으로 PR을 만들고 [PR 템플릿](../.github/PULL_REQUEST_TEMPLATE.md)에 변경·검증·미확인 범위를 요약한다.

세션 종료 조건은 코드 작성이 아니라 **검증·문서 최신화·PR 생성 완료**다. 세션 범위 밖 문제는 숨기지 않고 다음 세션 또는 별도 이슈로 남긴다. 테스트를 통과시키기 위한 가짜 프로덕션 로직은 추가하지 않는다.

### 검증 정책

- 세션의 공식 완료 검증은 **Playwright Electron E2E만** 사용한다.
- E2E는 Renderer → Preload → Main → 저장 → 화면으로 이어지는 실제 앱 배관과 사용자 여정을 프로덕션 번들에서 실행한다.
- 타입 검사나 하위 계층 테스트는 구현 보조 산출물일 수 있지만 세션 종료 검증으로 별도 실행하거나 보고하지 않는다.
- E2E로 확인할 수 없는 투명도, 외부 앱 포커스, Spaces, 실제 다중 모니터 같은 OS 합성 동작은 통과로 추정하지 않고 관련 이슈로 기록한다.

P1(S02~S06)은 2026-09-16 사용자 지시에 따른 일회성 예외로 세션별 E2E 선작성·실행을 생략하고, 전체 순수 코어 구현 후 타입 검사·Vitest 회귀·프로덕션 패키징으로 묶어서 검증했다. 아직 Main/IPC/Renderer에 연결되지 않은 규칙 코어의 대표 사용자 여정 E2E는 S09/S14에서 수행한다. 상세 결과는 [`session-reports/P1-blackjack-core.md`](session-reports/P1-blackjack-core.md)에 있다.

### 실행 순서와 P 단계 표기

P0~P3 표기는 [기술 설계서](blackjack-technical-design.md) §11.4가 정의하는 완료 판정 범주이지 세션이 반드시 따라야 하는 고정 실행 순서가 아니다. 세션 번호(S00~S18)는 이 로드맵이 정하는 실제 작업 순서이며, 아래처럼 범주를 의도적으로 교차 배치한다.

- 창 UI 마무리(P0 나머지)와 React 게임 UI 통합(P2 마지막)보다 게임 핵심 로직(P1)과 화면 없이 검증 가능한 백엔드 통합(P2 앞부분: GameStore·SessionRepository·IPC)을 먼저 끝낸다.
- 이유: `BlackjackCore`/`GameStore`/`SessionRepository`/IPC까지는 화면 없이 단위 테스트와 E2E(헤드리스 구동, 계약 검증)로 동작을 확정할 수 있고, 게임이 실제로 규칙대로 동작하는지가 창 크기·위치 저장 같은 UI 마감보다 우선순위가 높기 때문이다.
- P3(제품화 검증)는 그대로 마지막에 둔다.

## 2. 공통 세션 준비

### S00 — 테스트 실행 기반 정상화

**목표:** 이후 세션이 red → green 흐름으로 진행될 수 있는 실행 기반을 만든다.

- 설계: 기존 Playwright 설정과 격리된 `userData` 계약을 검토한다.
- 선행 검증: 현재 `@playwright/test` 미설치 상태와 기존 테스트 결과를 기록한다.
- 개발: `npm install`로 lockfile과 설치 상태를 동기화한다.
- 완료 조건:
  - `npx playwright test --list` 실행 가능
  - 프로덕션 번들에서 `npm run test:e2e` 실행 가능

## 3. P0 — 오버레이 창 프로토타입 (1단계)

### S01 — 커스텀 리사이즈

**목표:** 투명 창을 사용자 핸들로 220×150~420×280 DIP 범위에서 안정적으로 조절한다.

- 설계: resize start/update/end 계약, token, 좌표 기준, throttle, cancel·timeout 정책.
- E2E: 실제 BrowserWindow 크기 변경, 최소·최대 clamp, 잘못된 token/좌표 거부, 취소 후 무효화, UI 잘림 검증.
- 개발: Renderer 핸들 → Preload → IPC → Main `setBounds` 경로 구현.
- E2E 한계 기록: 투명도와 실제 외부 앱 포커스, Windows 실장비 동작은 자동 확인되지 않으면 관련 이슈로 남긴다.

## 4. P1 — 순수 BlackjackCore

### S02 — 카드·슈·점수 기반

**목표:** 6덱 슈와 결정론적 카드 공급, 핸드 점수 계산을 완성한다.

- 설계: Card/Shoe/Hand 모델, 고유 ID, Fisher–Yates 주입점, 컷 카드와 재셔플 조건.
- E2E: 앱의 결정론적 슈 주입 훅과 초기 딜 대표 경로를 red 상태로 작성한다.
- 단위 테스트: A 여러 장, soft/hard 합계, 312장 고유성, 75% 컷, 78장 안전 여유.
- 개발: core models, scoring, shoe 구현.

### S03 — 기본 라운드와 자연 블랙잭

**목표:** deal, hit, stand, 딜러 S17, 일반 승패·무승부·자연 블랙잭을 완성한다.

- 설계: betting → initialDeal → playerTurn → dealerTurn → settlement → result 전이.
- E2E: E2E-01~06 작성 또는 기존 초안을 실제 계약에 맞춰 확정.
- 단위 테스트: 플레이어/딜러/양쪽 블랙잭, S17, 버스트, 21 자동 종료.
- 개발: 기본 transition과 정산 구현.

### S04 — 보험·이븐 머니·서렌더

**목표:** 피크 순서와 별도 보험 정산을 정확히 구현한다.

- 설계: insuranceDecision, even money, peek, late surrender의 허용 시점과 원장 항목.
- E2E: E2E-07~10, E2E-13 작성.
- 단위 테스트: 보험 전 피크 금지, $0.50 단위, 보험 2:1, 이븐 머니 1:1, 서렌더 절반 반환.
- 개발: 관련 전이와 지급 구현.

### S05 — 더블·스플릿·다중 핸드

**목표:** 더블, DAS, 최대 4핸드, A 스플릿 제한을 완성한다.

- 설계: handId, activeHandIndex, 왼쪽 우선 진행, 추가금과 잔액 부족 처리.
- E2E: E2E-11~12 작성.
- 단위 테스트: 혼합 승패, 스플릿 21, A 재스플릿 금지, 한 장 종료, 오래된 handId.
- 개발: 다중 핸드 전이와 정산 구현.

### S06 — 코어 무결성과 정산 원장

**목표:** 모든 금액과 정산이 재실행에도 정확히 한 번만 적용되게 한다.

- 설계: `(roundId, componentId)` 키, safe integer, round net 계산, 무결성 오류.
- E2E: 잔액 부족·새 게임 대표 경로(E2E-15~16)를 작성한다.
- 단위 테스트: 보험/핸드 중복 지급, 경계 금액, 예상 밖 슈 소진, 혼합 정산.
- 개발: ledger와 검증 로직 보완 후 P1 전체 회귀.

## 5. P2 — 백엔드 통합 (화면 없이 GameStore·SessionRepository·IPC)

### S07 — GameStore 명령 직렬화

**목표:** Main 단일 작성자와 명령 중복·경합 방지를 구현한다.

- 설계: busy, `commandId`, `expectedRevision`, pendingTransition, 내부 딜러 명령.
- E2E: E2E-14 빠른 연속 클릭과 오래된 revision 경로 작성.
- 단위 테스트: 동일 ID 재전송, await 중 재진입, BUSY/STALE_STATE.
- 개발: GameStore 구현.

### S08 — SessionRepository와 복구

**목표:** 세션을 원자 저장하고 primary/backup에서 안전하게 복구한다.

- 설계: temp → sync → rename, backup, 버전·일관성 검증, 실패 후 재시도.
- E2E: E2E-17·19·20의 저장 체크포인트와 손상/미래 버전 시나리오 작성.
- 단위 테스트: 쓰기 실패, EPERM 재시도, 손상, 백업 복구, 응답 유실.
- 개발: SessionRepository와 GameStore 커밋 연결.

### S09 — IPC·Preload·상태 구독

**목표:** 목표 `BlackjackAPI`와 revision 기반 push 동기화를 완성한다.

- 설계: `getSnapshot`, `dispatch`, `onState`, sender 검증, 공개 ViewState 경계.
- E2E: E2E-21 보안 회귀와 snapshot/push 역순 시나리오 작성.
- 단위 테스트: subframe·낯선 URL·내부 명령·비정상 payload 거부, 홀 카드·슈 미노출.
- 개발: 계약, Zod 스키마, Main router, Preload bridge 구현.

## 6. P0 — 오버레이 창 프로토타입 마무리

### S10 — 접힘·펼침, 창 상태 모델과 불투명도 조절

S10 당시 보고서는 숨기기 전용 단축키를 기록한다. 이후 Alt+백틱이 숨김·복원 토글로 변경됐으며 현재 계약은 [제품 설계](blackjack-design.md#2-오버레이와-조작)를 따른다.

**목표:** 140×30 DIP 접힘 상태와 펼친 크기를 실행 중에 독립적으로 보존하고, 색상 전환 버튼 호버 조절창의 슬라이더로 전경 불투명도를 조절한다. 사용자 피드백에 따라 오해를 낳은 헤더 접기 버튼을 제거하고 Alt+백틱 전역 창 숨김·복원을 제공한다.

- 설계: `expanded | collapsed | hidden` 전이와 창 표시와 무관한 딜러 자동 진행 정책. 불투명도 20–100%(5% 단위, 기본 65%), 색상 버튼 호버 조절창·화면 경계 방향 선택과 미리보기 정책을 확정한다. 헤더 `▁` 버튼은 제거하되 내부 접힘 계약은 유지한다. Alt+백틱은 보이는 창을 숨기고 숨긴 창을 비활성 복원한다.
- E2E: 내부 접힘 명령의 크기·복원·판 보존·중복 방지와 헤더 접기 버튼 부재를 확인한다. 슬라이더 경계값·즉시 반영·접힘 중 값 유지·앱 재실행 기본값 복귀, 조절창의 화면 경계·호버 유지/닫힘을 검증한다. 패키지에서 전역 단축키 등록·숨김·복원 경로를 확인한다. 실제 물리 키 입력과 Tray 클릭은 수동 검증으로 남긴다.
- 개발: OverlayState와 접힘 UI·IPC·Main 크기 경로, 색상 버튼 호버의 작은 조절창과 불투명도 슬라이더를 구현한다. 헤더 접기 버튼을 제거하고 Main의 전역 단축키를 숨김·복원 경로에 연결한다. 불투명도는 게임 세션에 저장하지 않는다.
- E2E 한계 기록: 실제 OS 물리 키 입력, 외부 앱 포커스와 Tray 메뉴의 OS 동작은 자동 확인되지 않으면 관련 이슈로 남긴다.

### S10.5 — 금액 직접 입력과 게임 오버 경계 패치

**목표:** 베팅 금액을 텍스트 필드에 직접 입력하고 소수 둘째 자리까지 사용할 수 있게 한다. 판 정산 후 잔액이 $1.00 미만일 때 게임 오버가 되는지 검증한다.

- 설계: 베팅 금액 숫자칸을 클릭하면 같은 자리의 텍스트 필드로 전환한다. 평소 `focusable:false`인 오버레이는 명시적 편집 중에만 키보드 포커스를 받고, 종료 시 다시 비활성 상태로 돌아간다. $1.00~현재 사용 가능 잔액의 십진 금액을 정수 센트로 변환하며, 잘못된 입력은 확정·딜하지 않는다. 기존 −/+ 단위와 보험 $0.50 단위는 유지한다. 반 센트 반환금은 가장 가까운 센트로 반올림하고 정확히 반 센트는 올림한다.
- E2E 선작성: 숫자칸↔텍스트 필드 전환, Enter 확정·Escape/필드 밖 클릭 취소, 정수·소수 금액, 최소/최대·잔액 경계, 빈 값·문자·음수·소수 셋째 자리 거부와 딜 후 변경 불가를 검증한다. 편집 종료·숨김·접힘·reload 뒤 `focusable:false` 복귀를 확인한다. 정산 후 잔액 $1.00에서는 다음 판과 $1 베팅을 허용하고 $0.99에서는 게임 오버·다음 판/딜 차단·새 게임 안내를 확인한다. 라운드 중 잔액이 낮아져도 정산 지속을 확인한다. 저장 후 재기동 시 센트 베팅과 잔액도 보존한다.
- 개발: 인라인 텍스트 필드·편집 중 포커스 전환 IPC·문자열 파서, 코어 베팅·정산·무결성·저장 검증 및 베팅 UI를 갱신한다. 게임 오버는 잔액에서 계산하며 앱을 종료하거나 새 저장 phase를 만들지 않는다.
- 완료 조건: 선작성 E2E가 의도한 이유로 실패한 뒤 프로덕션 패키지 전체 E2E가 통과하고, 결과와 OS 포커스 한계를 세션 보고서에 기록한다. 실제 업무 앱의 포커스 복귀는 실장비에서 별도 확인한다.

### S11 — 위치·다중 모니터와 시작 기본값 (TOBE 보류)

**목표:** 실행 중 다중 모니터 배치를 안전하게 처리하고, 앱 재실행 때 창 표시 설정을 기본값으로 초기화한다. 게임 세션 복원은 그대로 유지한다.

**일정:** 사용자 결정(2026-09-17)으로 현 단계에서 제외한다. 아래 범위는 TOBE 백로그로 보존하며 다음 진행 세션은 S12다.

- 설계: 현재 디스플레이의 `workArea`, 음수 좌표, 모니터 분리 시 화면 안 보정과 시작 기본 위치를 정한다. 창 표시 설정은 디스크에 저장하지 않는다.
- E2E: 실행 중 화면 밖 좌표 보정, 재실행 시 기본 위치·크기·색상·불투명도·펼침·클릭 통과 해제를 확인하고 게임 판은 복원되는지 검증한다.
- 개발: DisplayPlacementService와 재실행 초기화 경로를 구현한다. `preferences.json`은 만들지 않는다.
- E2E 한계 기록: 물리 모니터 분리·재연결은 자동 확인되지 않으면 관련 이슈로 남긴다.

### S12 — 포커스·접근성 회귀

**목표:** S10.5에서 추가한 인라인 금액 편집과 후속 키보드·접근성 창의 OS 포커스 동작을 검증한다.

**범위:** 금액 직접 입력은 S10.5 인라인 텍스트 필드로 구현됐다. 별도 금액 입력 UtilityWindow는 만들지 않는다.

- 설계: 인라인 편집을 시작·종료할 때 OS 포커스 이동, 키보드/VoiceOver/Narrator 창과의 충돌 정책.
- E2E: 인라인 편집의 반복 시작·종료·메인 창 숨김/복원 후 상태와 키보드 경로를 회귀 검증한다.
- 개발: S10.5 이후 발견된 포커스·접근성 문제만 보완한다.
- E2E 한계 기록: 실제 업무 앱의 포커스 복귀는 OS별 실장비에서 확인한다.

### S13 — 클릭 통과와 P0 회귀

**목표:** 전체 클릭 통과와 Tray 복구를 안정화하고 S11을 제외한 현 단계 P0 범위의 완료 여부를 판정한다.

- 설계: interactive/passthrough 전이, 숨김·드래그·리사이즈와 충돌 정책.
- E2E: 모드 전환, Tray 명령, 재기동 후 Tray 복구 경로, Renderer 재로드 후 상태 유지. S11의 전체 창 설정 재실행 초기화는 요구하지 않는다.
- 개발: 누락된 상태 처리와 복구 경로 보완.
- E2E 한계 기록: 아래 앱 클릭·스크롤, Spaces·전체 화면은 자동 확인되지 않으면 관련 이슈로 남긴다. 자동 부분 통과(O-10)는 별도 실험이다.

## 7. P2 마무리 — React UI와 플레이 가능한 MVP

### S14 — React 게임 UI 통합

**목표:** 모든 게임 phase와 legalActions를 실제 화면에 연결한다.

- 설계: 상태별 컴포넌트, 활성 핸드, 결과 원장, 오류·저장 상태 표시.
- E2E: E2E-01~16을 실제 UI 클릭 기반으로 완성한다.
- 개발: 스텁 카드와 비활성 딜 버튼을 실제 ViewState 기반 UI로 교체한다.
- 검증: 최소·최대 창 크기, 11 DIP 글자, 24×24 DIP 클릭 영역, 카드 행 스크롤.

### S15 — 재기동 복원과 MVP E2E 완주

**목표:** 문서에 정의된 플레이 가능한 MVP 완료 기준을 충족한다.

- 설계: 강제 종료·정상 종료 뒤 자동 딜러 재개와 숨김·접힘 중 계속 진행하는 규칙을 확정한다.
- E2E: E2E-17의 10개 체크포인트와 E2E-19~20을 완성한다. E2E-18 창 설정 재실행 초기화는 S11과 함께 TOBE로 보류한다.
- 개발: 실패하는 복원 경로만 보완한다.
- 완료 조건: E2E-18(TOBE)을 제외한 E2E-01~21 결과를 있는 그대로 기록하고 현 단계 대상이 모두 통과할 때 P2 완료로 판정한다.
