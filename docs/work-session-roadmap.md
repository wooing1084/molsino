## 1. 재설계 기준

사용자가 정한 우선순위는 다음과 같다.

1. 소스 분석으로 치명적 버그를 찾고 확인된 문제가 있으면 개선한다.
2. 신규 게임을 추가한다. 메인 메뉴(게임 선택 페이지)를 먼저 제공하고 바카라를 연결한다.
3. 실제 사용 중 발견한 불편을 기준으로 기타 사용성을 개선한다.

구 계획의 S11 전체, S12~S18, 일부 구현된 S14의 잔여 범위, 다른 세션에서 넘긴 미완료 작업과 TOBE 백로그를 모두 폐기한다. 보류 목록으로 이관하지 않는다. 구 세션 번호와 P0~P3 완료 게이트는 새 작업에 재사용하지 않으며 **N01부터** 시작한다.

완료된 기능·코드·테스트와 [세션 보고서](session-reports/session-list.md)는 유지한다. 과거 보고서의 “다음 세션”은 당시 기록이다. 미검증 범위를 통과로 바꾸거나 실제 결함을 지우는 결정은 아니다. 기존 요구를 이유로 새 작업과 무관한 전체 회귀 확장·접근성 창·다중 모니터·성능·배포 세션을 자동 생성하지 않는다.

이번 설계의 소스 확인 범위와 한계는 [D01 보고서](session-reports/D01-roadmap-redesign.md)에 기록한다. 정적 사전 검토만으로 치명적 버그 부재를 증명하지 않는다.

## 2. 세션 운영 원칙

### 진행 절차

1. 현재 코드·관련 설계·최근 보고서를 확인하고 한 세션의 범위를 고정한다.
2. 최신 `DEV`에서 작업 브랜치를 만든다. 기본 이름은 `codex/nNN-주제`다.
3. 변경할 동작·실패 처리·완료 조건을 먼저 설계한다. 제품 결정이 필요하면 사용자에게 질문하며 독립적인 작업을 계속한다.
4. 기능 추가·버그 수정은 기대 동작의 E2E를 먼저 작성한다. 버그는 같은 조건의 실패, 새 기능은 미구현에 따른 실패를 확인한다.
5. 필요한 구현을 진행하고 프로덕션 패키지 E2E로 완료 조건을 확인한다.
6. 담당 설계·구현 현황·E2E 현황과 세션 보고서를 갱신한다.
7. 코드·테스트·문서를 커밋하고 작업 브랜치에 push한 뒤 `DEV` 대상 PR을 생성한다.

기능 세션은 검증·문서 최신화·PR 생성까지 완료한다. 분석에서 결함을 찾지 못한 N01이나 문서만 변경한 설계 세션은 재현하지 않은 실패·수정·통과를 만들지 않고 분석 범위·결론·문서 점검을 기록한다.

### 검증 정책

- 기능 세션의 공식 완료 검증은 **Playwright Electron E2E**다. 프로덕션 패키지의 실제 Main·Preload·Renderer·저장 경로를 사용하고 명령은 `package.json`을 따른다.
- 규칙표·정수 금액 연산은 하위 계층 테스트를 구현 보조로 활용한다. 타입 검사·하위 테스트를 실제 플레이 완료로 대신 보고하지 않는다.
- 기존 테스트를 활용하고 새 동작과 재현된 위험에 필요한 검증만 추가한다. 변경과 무관한 구 계획의 모든 미작성 테스트를 완성할 의무는 없다.
- N04는 실제 앱의 제한된 IPC를 거치는 백엔드 통합 E2E까지이며 화면 클릭 기반 플레이 완료는 N05에서 판정한다.
- 실제 외부 앱 포커스·물리 단축키·OS 합성은 관찰한 범위만 기록한다. 미확인을 통과로 추정하지 않는다. 관련 변경·문제가 없으면 별도 OS 검증 프로젝트로 확대하지 않는다.
- 문서만 변경한 경우 링크·참조·결정 일관성을 점검하며 앱 전체 E2E를 의무 실행하지 않는다.

## 3. 새 세션 순서

| 순서 | 세션 | 사용자가 얻는 결과 | 선행 조건 |
| --- | --- | --- | --- |
| 1 | N01 치명적 버그 분석·개선 | 저장 손실·잘못된 정산·진행 불능 등 실제 문제의 확인과 필요한 수정 | 현재 코드 |
| 2 | N02 공용 잔액·저장 전환 | 기존 블랙잭 자산과 판을 보존하는 여러 게임용 저장 기반 | 확인된 치명적 결함 해결 |
| 3 | N03 메인 메뉴 | 공용 잔액과 게임 선택, 판 종료 후 메뉴 이동 | N02 |
| 4 | N04 바카라 규칙·백엔드 | 기본 바카라 베팅·자동 배분·정산·저장 | N02·N03 |
| 5 | N05 바카라 화면·통합 | 두 게임을 선택해 같은 잔액으로 플레이 | N04 |
| 6 | N06 사용성 개선 | 실제 불편 중 사용자가 고른 개선 | N05 플레이 피드백 |

N02는 메인 메뉴에 필요한 저장 기반이다. 블랙잭을 공용 잔액에 연결해 플레이 가능한 상태로 끝낸다. N03의 바카라 항목은 N05 완료 전까지 준비 중이며 선택할 수 없다.

## 4. N01 — 치명적 버그 분석과 필요한 수정

**목표:** 확인된 문제에 근거해 신규 게임 작업을 시작할 수 있는지 판단한다.

- 분석: 베팅 차감·보험/스플릿/더블 정산·명령 재전송, 저장 실패/재시도/종료/복구, 앱 시작·Renderer 장애, IPC 신뢰 경계를 확인한다.
- 치명적 문제는 확정된 판·잔액 손실/오염, 실제 정산 오류, 핵심 플레이 불능, 신뢰 경계 침해처럼 구체적인 사용자 피해가 있는 결함이다.
- 후보별 소스 위치·발생 조건·예상/실제 결과·재현 방법·영향·확정 여부를 기록한다. 기능 미구현이나 테스트 부족만으로 치명적 버그라고 부르지 않는다.
- 기존 방어 코드와 테스트를 먼저 확인한다. [D01 사전 검토](session-reports/D01-roadmap-redesign.md)의 후보도 독립적으로 검증한다.
- 확정된 결함에만 재현 E2E와 수정을 추가한다. 독립적인 대형 결함은 발견 후 범위가 명확한 N01 후속 세션으로 나눈다.

**완료 조건:** 분석 범위·재현 결과를 보고하고 확인된 치명적 결함은 수정·회귀 검증한다. 미발견이면 “조사 범위 내 확정 결함 없음”으로 종료해 N02로 이동한다. 전면 리팩터링은 완료 조건이 아니다.

## 5. N02 — 공용 잔액과 저장 전환

**목표:** 블랙잭과 바카라가 함께 쓸 잔액을 Main에서 한 번만 관리한다.

- [공용 상태 계약](main/technical-design.md#9-여러-게임과-공용-잔액의-신규-계약)에 따라 잔액·게임별 상태·진행 중 게임·revision을 하나의 원자 저장 단위로 만든다.
- 기존 블랙잭 `session.json`의 잔액·카드·슈·진행 phase·처리 명령을 보존해 이전한다. 신규 초기 금액을 추가 지급하지 않는다.
- 블랙잭 코어 어댑터와 앱 공통 API를 도입한다. 게임별 잔액 복제와 파일별 분리 정산을 허용하지 않는다.
- 구 파일 보존, 이관 중단·재시도, 새 형식 손상·미래 버전 복구를 구현한다.
- 새 시작은 앱 전체 동작으로 이동하고 진행 중 게임에서는 거부한다. UI 연결은 N03에서 완성한다.

**E2E:** 센트 잔액·보험/스플릿 등 미완료 판 이전, 구 파일 불변, 이관 재실행 시 중복 지급 없음, 저장 실패/재시도, 재기동 후 같은 판, 블랙잭 대표 정산과 공용 잔액 일치. [메인 APP 시나리오](main/e2e-test-plan.md)를 따른다.

**완료 조건:** 기존 사용자가 금액·판을 잃지 않고 블랙잭을 계속 플레이한다. 바카라 상태는 아직 미생성이어도 된다.

## 6. N03 — 메인 메뉴와 게임 이동

**목표:** 같은 오버레이 안에서 게임을 선택하고 판 종료 후 메뉴로 돌아온다.

- 공용 잔액과 블랙잭·바카라 항목, 전체 새 시작을 가진 메뉴를 만든다. [메인 제품 설계](main/product-design.md#5-메인-메뉴와-공용-잔액의-신규-설계)를 따른다.
- 미완료 판이 없으면 메뉴로 시작하고 있으면 해당 게임을 복원한다.
- 베팅 전·정산 완료 때 메뉴 이동을 허용한다. 진행 중·저장 중·저장 실패 때는 Main에서도 거부하고 금액 입력 초안은 이동 시 취소한다.
- 이동이 셔플·재충전·중복 정산을 일으키지 않게 한다. 게임별 슈·결과·베팅 설정은 보존한다.
- 바카라는 준비 중으로 표시하며 실제 구현된 게임만 실행할 수 있게 검증한다.

**E2E:** 메뉴→블랙잭→결과→메뉴, 진행 중 직접 IPC 이동 거부, 메뉴와 딜의 동시 명령, 재실행 화면 선택, 편집 중 이동, 최소 크기 메뉴·헤더, 숨김·복원, 새 시작 취소/확정과 $100 초기화.

**완료 조건:** 메뉴·공용 잔액이 연결되고 블랙잭 플레이를 유지한다. 미완성 바카라로 잘못 진입하지 않는다.

## 7. N04 — 바카라 규칙과 백엔드 통합

**목표:** 기본 바카라를 순수 규칙부터 공용 저장까지 연결한다.

- [바카라 제품 설계](games/baccarat/product-design.md)의 점수·내추럴·세 번째 카드·배당·센트 반올림·슈 정책을 구현한다.
- [바카라 기술 설계](games/baccarat/technical-design.md)의 전이·차감·정산·중복 명령·저장 실패·복구·최근 결과를 공용 작성자에 연결한다.
- 블랙잭 6덱 규칙과 바카라 규칙을 분리하고 공유할 가치가 있는 카드 표현·순수 셔플만 재사용한다.
- 결정론적 바카라 슈를 준비하며 Renderer에 슈·미공개 카드를 전달하지 않는다.

**검증:** 세 번째 카드 규칙표·배당 경계는 하위 테스트로 보조한다. 공식 E2E는 실제 앱의 IPC→공용 작성자→규칙→저장→공개 상태를 거쳐 세 결과, Tie 원금 반환, 센트 정산, 중복 지급 방지, 자동 진행 복원을 확인한다.

**완료 조건:** 실제 앱 백엔드에서 바카라 한 판이 공용 잔액을 정확히 차감·정산·복원한다. 테스트 경로가 일반 사용자에게 미완성 게임 진입을 허용하지 않는다. UI 완성은 N05다.

## 8. N05 — 바카라 플레이 화면과 통합 완성

**목표:** 메뉴에서 바카라를 선택해 베팅부터 결과까지 플레이한다.

- Player/Banker 카드·점수, 한 곳 베팅·금액, 딜, 결과·순손익·다음 판·메뉴, 최근 P·B·T 한 줄을 연결한다.
- 결과 연출은 저장된 결과를 표시한다. 화면 재생이나 숨김·복원이 정산·기록을 다시 실행하지 않는다.
- 최소 220×150 DIP에서 읽고 조작할 수 있게 배치한다. 흑백·불투명도·Alt+백틱 계약을 유지한다.
- 바카라를 활성화하고 블랙잭→메뉴→바카라→메뉴의 공용 잔액·게임별 슈 보존을 완성한다.
- 미완료 바카라 재기동·정산 직후 재기동·저장 오류·잔액 부족·전체 새 시작을 화면으로 검증한다.

**E2E:** [바카라 E2E 설계](games/baccarat/e2e-test-plan.md)·[메인 APP 시나리오](main/e2e-test-plan.md)를 UI 클릭으로 검증하고 변경된 공용 경로의 블랙잭 회귀도 실행한다.

**완료 조건:** 같은 잔액으로 두 게임을 번갈아 플레이하고 판 중 이동은 차단되며 정상·강제 종료 후 판·금액이 일치한다. 화면·정산·복구까지 통과한 뒤 바카라를 제공 기능으로 표시한다.

## 9. N06 — 사용성 개선 선정과 구현

**목표:** 두 게임을 사용하며 확인한 불편을 개선한다.

구체적인 항목은 아직 확정하지 않는다. N05 이후 사용자 불편·아이디어를 받아 발생 빈도·영향으로 순서를 정하고 한 세션 분량을 선택한다. 문제 장면과 기대 동작을 기록한 뒤 필요한 설계·검증·수정을 진행한다.

구 S12~S18과 TOBE 목록을 통째로 옮기지 않는다. 접근성·창 복구·성능 등도 실제 요구나 발견된 문제를 근거로 새로 선정한다. 치명적 결함은 이 순서와 관계없이 먼저 처리한다.

**완료 조건:** 선정한 불편의 전후 차이를 설명하고 관련 검증을 통과한다. 선정 전에는 구현 일정·완료를 약속하지 않는다.
