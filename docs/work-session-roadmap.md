| 순서 | 세션 | 사용자에게 제공하는 결과 |
| --- | --- | --- |
| 1 | N02 메인 메뉴와 블랙잭 분리 | 메뉴에서 블랙잭 진입, 앱 공통 잔액·저장·복구·새 시작 |
| 2 | N03 바카라 구현 | 이미 분리된 앱 기반에 바카라 규칙·저장·화면을 연결해 두 게임 플레이 |
| 3 | N04 게임성 개선 | 투명도 조절창 동기화·레벨별 베팅 한도·순차 카드 공개 |

| 5 | N06 macOS 서명과 Mac App Store 제출 | 스토어용 서명 빌드 검증·업로드·심사 제출 |

## 2. 세션 운영 원칙

1. 현재 코드·관련 설계·최근 보고서를 확인하고 범위를 설계한다.
2. 최신 `DEV`에서 `codex/nNN-주제` 작업 브랜치를 만든다.
3. 기대 동작의 E2E를 먼저 작성하고 미구현/결함에 의한 실패를 확인한다.
4. 구현 후 프로덕션 패키지의 Playwright Electron E2E로 확인한다. 하위 테스트·타입 검사만으로 플레이 완료를 주장하지 않는다.
5. 변경에 관련된 회귀만 검증하고 담당 설계·구현 현황·E2E 현황과 보고서를 갱신한다.
6. 커밋·작업 브랜치 push·`DEV` 대상 PR 생성까지 진행한다.

외부 앱 포커스·물리 키·트레이·OS 합성은 실제 관찰한 범위만 기록한다. 미확인을 통과로 추정하거나 별도 대규모 검증 프로젝트로 확대하지 않는다.

## 3. N02 — 메인 메뉴와 블랙잭 분리

**목표:** 블랙잭 전용 앱을 메인 영역과 블랙잭 영역으로 분리한다. 바카라는 준비 중으로 표시하며 선택·플레이를 허용하지 않는다.

### 1. 공용 상태·저장·기존 데이터 이전

- Main의 `AppStore`가 공용 지갑·화면·게임별 상태·진행 판 잠금·revision을 한 번에 저장한다.
- 블랙잭은 순수 코어와 어댑터를 통해 공용 잔액을 입력받고 결과 잔액을 반환한다. 게임 상태에는 잔액을 중복 저장하지 않는다.
- 기존 `session.json`의 잔액·슈·카드·보험/스플릿·phase·원장·직전 명령을 보존하여 `app-session.json`으로 이전한다. 기존 파일은 변경하지 않으며 $100을 추가 지급하지 않는다.
- 새 파일/백업 우선순위·손상/미래 버전·이전 재시도·저장 후보 재시도를 구현한다.

**완료 조건:** 기존 사용자가 금액과 진행 판을 잃지 않고 이어서 블랙잭을 플레이한다.

### 2. 메인 메뉴·앱 공통 API·화면 분리

- `window.molsino`의 앱 명령·구독·snapshot과 창 API를 사용한다. 앱 공개 상태 안에서 블랙잭 공개 상태를 분리한다.
- 메뉴에 공용 잔액·블랙잭·바카라 준비 중·전체 새 시작을 표시한다.
- 미완료 판이 없으면 메뉴로 시작하며 있으면 해당 게임을 복원한다. Renderer reload는 현재 화면을 유지한다.
- 베팅 전·결과 저장 후만 이동을 허용한다. 저장 중·저장 실패·진행 중의 이동·초기화는 Main에서도 거부한다.
- 메인 Renderer는 오버레이·메뉴·복구를, 별도 블랙잭 컴포넌트는 카드·행동·금액 입력을 담당한다.
- 전체 새 시작은 메뉴의 명시적 취소/확정 뒤 $100·새 세션 ID·빈 게임 상태를 원자 저장한다.

**완료 조건:** 최소 220×150에서 메뉴→블랙잭→결과→메뉴를 조작하며, 게임 이동이 셔플·재충전·중복 정산을 발생시키지 않는다.

### 3. 통합 검증과 문서

[메인 APP 시나리오](main/e2e-test-plan.md)의 단일 게임 적용 범위, 기존 블랙잭 정산·보험/스플릿 이전·재실행·저장 오류·IPC 신뢰·입력·오버레이 회귀를 검증한다. APP-08의 두 게임 왕복은 N03에서 완료한다. 문서 최신화·보고서·PR까지 완료한다.

## 4. N03 — 바카라 구현

**목표:** N02의 앱 기반을 사용해 기본 바카라를 실제 화면에서 플레이한다.

- [바카라 제품 설계](games/baccarat/product-design.md)와 [기술 설계](games/baccarat/technical-design.md)에 따라 8덱·세 번째 카드·한 곳 베팅·Banker 수수료 5%·Tie 순이익 8배를 구현한다.
- 공용 작성자에 단계별 배분·정산·자동 진행·복구·최근 P/B/T 20개 기록을 연결한다.
- 바카라 화면을 추가하고 메뉴에서 활성화한다. 최소 크기·금액 입력·흑백·불투명도·숨김 계약을 유지한다.
- [바카라 E2E](games/baccarat/e2e-test-plan.md)와 APP-08을 통해 두 게임 왕복·공용 잔액·게임별 슈·저장 오류·종료 복원을 검증한다.

**완료 조건:** 백엔드만으로 완료하지 않는다. 메뉴 선택부터 카드·결과·재기동 복구·두 게임 왕복까지 실제 UI E2E와 관련 블랙잭 회귀를 통과하고 문서·PR을 완료한다.

## 5. N04 — 게임성 개선

2026-09-21 사용자 플레이 피드백으로 아래 세 항목을 선정했다. 초기 정책 구현·검증과 DEV 대상 PR 생성을 완료했다. 적용한 정책과 기준 문서 연결은 [N04 게임성 개선 설계 결정](main/gameplay-improvements-design.md)을, 실제 실행 기록은 [N04 보고서](session-reports/N04-gameplay-improvements.md)를 따른다.

- 별도 투명도 조절 슬라이더 창이 게임 창과 같은 불투명도를 사용한다.
- 공용 잔액에 따른 테이블 레벨과 모든 게임에 동일한 최소·최대 베팅 한도를 추가한다. 메뉴에서 좌우 카드로 레벨을 선택하고, 상단의 현재 레벨과 게임 화면의 베팅 한도를 상시 표시한다.
- 두 게임의 카드를 시간차를 두고 공개하며 합계·결과·잔액의 선행 노출을 막는다.

**완료 조건:** 설계 확정 후 관련 E2E를 선작성하고 실제 프로덕션 패키지에서 최소 크기 조작·한도 경계·저장 복구·카드 공개 순서·숨김 복원을 검증한다. 문서·보고서·PR을 완료한다. 이번 설계안 작성만으로 구현 완료 처리하지 않는다.

## 6. N05 — 빅휠 구현

2026-09-21 사용자 요청으로 사이닝보다 먼저 진행한다. [빅휠 제품·게임 규칙](games/bigwheel/product-design.md)과 [기술 설계](games/bigwheel/technical-design.md)를 구현 시작 전에 작성했다.

- 강원랜드 공식 54칸·7구역 배분과 배당을 적용하고 복수 구역 베팅·회전 후 변경 금지·순손익을 구현한다.
- 공용 잔액·레벨 한도·Main 전용 추첨·자동 정산·v4 저장과 이전·진행 판 복원을 연결한다.
- 메뉴 진입과 휠·베팅·결과·최근 기록 화면을 최소 220×150에 맞추고 결과의 선행 노출을 막는다.
- 순수 규칙/저장 검증 및 프로덕션 패키지 E2E로 세 게임 이동·저장 재시도·재기동·표시를 확인한다.

**완료 조건:** 게임 설계·실제 플레이·관련 회귀·담당 문서·세션 보고서·DEV 대상 PR을 완료한다. 세부 규칙의 유일한 기준은 게임 문서이며 공식 규칙과 앱 운영 결정을 구분한다.

2026-09-23 후속: [세 칸 확대 표시 설계](games/bigwheel/product-design.md#31-결과-주변-세-칸-확대)를 반영했다. BW-11~14를 선작성한 뒤 현재 작업 브랜치에서 구현·검증했다. [후속 보고서](session-reports/N05-bigwheel-result-zoom.md)에 결과를 기록한다.

## 7. N06 — macOS 서명과 Mac App Store 제출

기존 Apple Developer 계정을 사용해 스토어용 빌드와 제출을 진행한다. N05 이후에 착수한다.

- 출시 국가·가격·계정 유형과 모의 도박 연령 등급·한국 배포 시 등급분류번호 요구를 확인한다.
- Bundle ID·앱 레코드·인증서·프로비저닝 프로파일을 준비한다.
- Electron MAS·App Sandbox·앱/Helper 권한·서명된 PKG 생성 경로를 구성한다.
- 개발용 서명 MAS 앱에서 게임·저장·투명 창·클릭 통과·단축키·트레이·외부 앱 포커스를 검증한다.

**완료 조건:** 스토어 빌드 검증·업로드 처리 성공·심사 제출을 확인하고 문서·보고서·PR을 완료한다. 심사 승인과 실제 공개는 별도 상태로 기록한다. 제출 시점의 공식 요구사항을 다시 확인한다.
