## 1. 범위와 우선순위

출시 전 추가 개발은 아래 N07·N08로 한정한다. 창 위치 복귀·설정 저장 확대·새 게임·계정·클라우드·수익화는 이 두 세션에 포함하지 않는다. N09의 서명·제출 준비는 별도로 유지한다.

## 2. 세션 운영 원칙

1. 현재 코드·관련 설계·최근 보고서를 확인하고 범위를 설계한다.
2. 최신 `DEV`에서 `codex/nNN-주제` 작업 브랜치를 만든다.
3. 제품 코드를 바꾸는 세션은 기대 동작의 E2E를 먼저 작성하고 미구현/결함에 의한 실패를 확인한다. N07처럼 문서만 바꾸는 세션은 설명과 실제 UI·소스의 대조, 문서 링크·앵커 확인으로 검증하며 새 자동 테스트를 요구하지 않는다.
4. 제품 코드 구현 후 프로덕션 패키지의 Playwright Electron E2E로 확인한다. 하위 테스트·타입 검사만으로 플레이 완료를 주장하지 않는다.
5. 변경에 관련된 회귀만 검증하고 담당 설계·구현 현황·E2E 현황과 보고서를 갱신한다.
6. 커밋·작업 브랜치 push·`DEV` 대상 PR 생성까지 진행한다.

외부 앱 포커스·물리 키·트레이·OS 합성은 실제 관찰한 범위만 기록한다. 미확인을 통과로 추정하거나 별도 대규모 검증 프로젝트로 확대하지 않는다.

## 3. N02 — 메인 메뉴와 블랙잭 분리

**목표:** 블랙잭 전용 앱을 메인 영역과 블랙잭 영역으로 분리한다. 바카라는 준비 중으로 표시하며 선택·플레이를 허용하지 않는다.

### 1. 공용 상태·저장·기존 데이터 이전

- Main의 `AppStore`가 공용 지갑·화면·게임별 상태·진행 판 잠금·revision을 한 번에 저장한다.
- 블랙잭은 순수 코어와 어댑터를 통해 공용 잔액을 입력받고 결과 잔액을 반환한다. 게임 상태에는 잔액을 중복 저장하지 않는다.
- 기존 `session.json`의 잔액·슈·카드·보험/스플릿·phase·원장·직전 명령을 보존하여 `app-session.json`으로 이전한다. 기존 파일은 변경하지 않으며 $100을 추가 지급하지 않는다.
- 새 파일/백업 우선순위·손상/미래 버전·이전 재시도·저장 후보 재시도를 구현한다.

**완료 조건:** 기존 사용자가 금액과 진행 판을 잃지 않고 이어서 블랙잭을 플레이한다.

### 2. 메인 메뉴·앱 공통 API·화면 분리

- `window.molsino`의 앱 명령·구독·snapshot과 창 API를 사용한다. 앱 공개 상태 안에서 블랙잭 공개 상태를 분리한다.
- 메뉴에 공용 잔액·블랙잭·바카라 준비 중·전체 새 시작을 표시한다.
- 미완료 판이 없으면 메뉴로 시작하며 있으면 해당 게임을 복원한다. Renderer reload는 현재 화면을 유지한다.
- 베팅 전·결과 저장 후만 이동을 허용한다. 저장 중·저장 실패·진행 중의 이동·초기화는 Main에서도 거부한다.
- 메인 Renderer는 오버레이·메뉴·복구를, 별도 블랙잭 컴포넌트는 카드·행동·금액 입력을 담당한다.
- 전체 새 시작은 메뉴의 명시적 취소/확정 뒤 $100·새 세션 ID·빈 게임 상태를 원자 저장한다.

**완료 조건:** 최소 220×150에서 메뉴→블랙잭→결과→메뉴를 조작하며, 게임 이동이 셔플·재충전·중복 정산을 발생시키지 않는다.

### 3. 통합 검증과 문서

[메인 APP 시나리오](main/e2e-test-plan.md)의 단일 게임 적용 범위, 기존 블랙잭 정산·보험/스플릿 이전·재실행·저장 오류·IPC 신뢰·입력·오버레이 회귀를 검증한다. APP-08의 두 게임 왕복은 N03에서 완료한다. 문서 최신화·보고서·PR까지 완료한다.

## 4. N03 — 바카라 구현

**목표:** N02의 앱 기반을 사용해 기본 바카라를 실제 화면에서 플레이한다.

- [바카라 제품 설계](games/baccarat/product-design.md)와 [기술 설계](games/baccarat/technical-design.md)에 따라 8덱·세 번째 카드·한 곳 베팅·Banker 수수료 5%·Tie 순이익 8배를 구현한다.
- 공용 작성자에 단계별 배분·정산·자동 진행·복구·최근 P/B/T 20개 기록을 연결한다.
- 바카라 화면을 추가하고 메뉴에서 활성화한다. 최소 크기·금액 입력·흑백·불투명도·숨김 계약을 유지한다.
- [바카라 E2E](games/baccarat/e2e-test-plan.md)와 APP-08을 통해 두 게임 왕복·공용 잔액·게임별 슈·저장 오류·종료 복원을 검증한다.

**완료 조건:** 백엔드만으로 완료하지 않는다. 메뉴 선택부터 카드·결과·재기동 복구·두 게임 왕복까지 실제 UI E2E와 관련 블랙잭 회귀를 통과하고 문서·PR을 완료한다.

## 5. N04 — 게임성 개선

2026-09-21 사용자 플레이 피드백으로 아래 세 항목을 선정했다. 초기 정책 구현·검증과 DEV 대상 PR 생성을 완료했다. 적용한 정책과 기준 문서 연결은 [N04 게임성 개선 설계 결정](main/gameplay-improvements-design.md)을, 실제 실행 기록은 [N04 보고서](session-reports/N04-gameplay-improvements.md)를 따른다.

- 별도 투명도 조절 슬라이더 창이 게임 창과 같은 불투명도를 사용한다.
- 공용 잔액에 따른 테이블 레벨과 모든 게임에 동일한 최소·최대 베팅 한도를 추가한다. 메뉴에서 좌우 카드로 레벨을 선택하고, 상단의 현재 레벨과 게임 화면의 베팅 한도를 상시 표시한다.
- 두 게임의 카드를 시간차를 두고 공개하며 합계·결과·잔액의 선행 노출을 막는다.

**완료 조건:** 설계 확정 후 관련 E2E를 선작성하고 실제 프로덕션 패키지에서 최소 크기 조작·한도 경계·저장 복구·카드 공개 순서·숨김 복원을 검증한다. 문서·보고서·PR을 완료한다. 이번 설계안 작성만으로 구현 완료 처리하지 않는다.

## 7. N06 — 영어 현지화

2026-09-23 사용자 요청으로 기존 N06 스토어 제출보다 먼저 진행한다. [메인 제품 설계 §7](main/product-design.md#7-한국어영어와-네이티브-언어-메뉴)과 [기술 설계 §10](main/technical-design.md#10-영어-현지화와-네이티브-언어-메뉴)을 구현 기준으로 삼는다.

- 기존 한국어를 기본값으로 유지하고 영어 한 언어를 추가한다. 게임·잔액·저장 형식과 규칙은 언어 때문에 바꾸지 않는다.
- 오버레이 안에는 언어 설정 UI를 넣지 않는다. macOS는 애플리케이션 메뉴와 상태 아이콘 메뉴, Windows는 알림 영역 트레이 메뉴를 사용한다.
- Main이 별도 환경설정 파일의 언어를 소유하고 Renderer·불투명도 창·네이티브 메뉴를 즉시 동기화한다. 전체 새 시작과 게임 세션 복구는 언어 설정을 초기화하지 않는다.
- 메인 메뉴·레벨·복구·세 게임·접근성 이름·입력/저장 오류·네이티브 대화상자를 영어로 제공한다. raw 한국어 오류를 영어 화면에 노출하지 않는다.
- 기대 동작의 N06 E2E를 선작성해 기존 패키지에서 실패를 확인한 뒤 구현하고, 프로덕션 패키지에서 전환·재실행·진행 판 불변·최소 창을 확인한다.

**완료 조건:** 한국어/영어 네이티브 메뉴, 전체 사용자 표시, 별도 설정 저장과 실패 경계, 관련 단위·프로덕션 패키지 E2E, 담당 문서·보고서·DEV 대상 PR을 완료한다. macOS 자동화의 Windows 템플릿 검사를 실제 Windows 트레이 UI 검증으로 주장하지 않는다.

2026-09-23 완료: 위 범위를 구현하고 macOS arm64 프로덕션 패키지에서 언어 전환·재실행·진행 판 불변·최소 창과 관련 회귀를 검증했다. 상세 결과와 실제 미검증 범위는 [N06 보고서](session-reports/N06-english-localization.md)를 따른다.

## 8. N07 — Markdown 사용 설명서 작성

**목표:** 개발 지식 없이 설치한 사용자가 문서를 읽고 창을 조작하며 세 게임을 한 판씩 플레이할 수 있다. 상세 작성 기준은 [사용 설명서 작성 설계](main/user-guide-design.md)를 따른다.

**시작 자료:** `AGENT.md` → [문서 안내](README.md) → [사용 설명서 설계](main/user-guide-design.md), 메인·세 게임 제품 설계와 현재 Renderer·네이티브 메뉴. 최신 `DEV`에서 `codex/n07-user-guide`로 시작한다.

- 루트에 `USER_GUIDE.md` 한 파일을 만든다. 한국어와 English 절에 같은 핵심 조작을 제공하고 목적·요약·목차로 시작한다.
- 빠른 시작, 창 이동·크기·흑백·불투명도·숨김/복원·클릭 통과, 언어 메뉴, 공용 잔액·레벨·베팅 입력, 세 게임의 기본 규칙과 한 판 흐름, 저장·재실행·새 시작과 문제 해결을 설명한다.
- `$`는 구매·환전·현금 보상이 없는 가상 게임 머니임을 밝힌다. 실제 표시되는 버튼·메뉴를 기준으로 쓰고 개발 명령·내부 저장 구조·미구현 기능을 사용자 절차에 넣지 않는다.
- `README.md`에 사용 설명서 진입 링크를 추가하고 문서 색인·작성 가이드에 역할을 연결한다. 이 세션은 앱 안의 도움말 화면·메뉴나 웹사이트를 만들지 않는다.
- 작성 당시의 실제 언어 정책을 설명한다. 이후 N08에서 첫 실행 정책을 구현하면 이 설명서와 README의 언어 안내도 같은 세션에서 갱신한다.
- 실제로 사용할 수 있는 경로와 버튼을 대조하고 두 언어의 안내·상대 링크·앵커를 확인한다. 새 앱 테스트·패키징은 문서 변경만으로 강제하지 않는다.

**완료 조건:** README에서 설명서로 이동해 창 복원·클릭 통과 해제·베팅 입력 확정/취소·세 게임의 한 판·잔액 부족 시 새 시작을 찾아 따라갈 수 있다. 현재 미구현 기능을 제공한다고 쓰지 않는다. 담당 문서·N07 보고서·세션 목록·PR을 완료한다.

## 9. N08 — 실행 언어 유지와 첫 실행 언어 선택

**목표:** 설정이 없는 첫 실행은 시스템 선호 언어로 시작하고 이후에는 저장한 언어를 우선한다. 언어 선택의 재실행 보존은 N06에서 이미 구현됐으므로 이를 새 기능처럼 다시 만들지 않는다.

**시작 자료:** N07 완료 후 최신 `DEV`에서 `codex/n08-startup-locale`로 시작한다. [제품 설계 §7.1](main/product-design.md#71-n08-실행-언어-유지와-첫-실행-언어-선택), [기술 설계 §10.5](main/technical-design.md#105-n08-첫-실행-언어-결정과-보존), [N08 검증 기준](main/e2e-test-plan.md#6-n08-실행-언어-유지와-첫-실행-언어-선택), 현재 preferences 저장소·Main 시작 경로·N06 테스트를 먼저 읽는다.

- 설정의 primary·backup이 모두 없는 경우에만 시스템 선호 목록에서 첫 지원 언어를 고른다. 한국어·영어 지역 변형을 인식하고 지원 언어가 없거나 조회에 실패하면 영어로 시작한다.
- 계산한 첫 실행 언어를 기존 `preferences.json` 형식으로 저장한다. 기존 한국어·영어 파일과 유효한 백업은 시스템 언어보다 우선하고 기존 한국어 기본값도 그대로 보존한다.
- 재실행·Renderer reload·전체 새 시작·앱 업데이트에서 같은 userData의 설정을 유지한다. 시스템 언어 변경으로 앱의 저장된 언어를 덮어쓰지 않는다.
- 초기/백업 복구 저장 실패와 사용자의 언어 변경 저장 실패를 구분하고, 설정 손상·미래 형식·읽기 실패가 게임 복구를 막지 않게 한다. 정확한 우선순위·실패 계약은 제품·기술 설계가 기준이다.
- 결정론적인 시스템 언어 입력으로 N08 E2E를 선작성하고 기존 한국어 기본값에서 실패를 확인한다. 기존 한국어 테스트의 실행 환경 의존성을 없애고 N06 보존·전환·저장 실패와 관련 게임 회귀를 확인한다.
- N07의 사용 설명서·README 언어 안내, 담당 설계·구현/E2E 현황과 N08 보고서를 갱신한다. 새 언어·자동 전환 모드·창 설정·게임 저장 형식 변경은 범위 밖이다.

**완료 조건:** 첫 실행의 한국어/영어 선택, 기존 설정·백업의 우선, OS 언어 변경 후 재실행 보존과 실패 경계를 단위 테스트·프로덕션 패키지 E2E로 확인한다. 문서·세션 목록·PR을 완료하고 실제 OS 언어 조회/Windows 검증 여부는 관찰한 범위만 기록한다.

## 10. N09 — macOS 서명과 Mac App Store 제출

기존 Apple Developer 계정을 사용해 스토어용 빌드와 제출을 진행한다. N07 사용 설명서와 N08 실행 언어 세션 이후에 착수한다. 기존 미착수 N07의 제출 범위를 이 세션으로 이동했다.

- 출시 국가·가격·계정 유형과 모의 도박 연령 등급·한국 배포 시 등급분류번호 요구를 확인한다.
- Bundle ID·앱 레코드·인증서·프로비저닝 프로파일을 준비한다.
- Electron MAS·App Sandbox·앱/Helper 권한·서명된 PKG 생성 경로를 구성한다.
- 개발용 서명 MAS 앱에서 게임·저장·투명 창·클릭 통과·단축키·트레이·외부 앱 포커스를 검증한다.
- 스토어 설명·스크린샷·지원/개인정보처리방침 URL·신고 사항·심사 메모를 준비하고 업로드·심사 제출한다.

**완료 조건:** 스토어 빌드 검증·업로드 처리 성공·심사 제출을 확인하고 문서·보고서·PR을 완료한다. 심사 승인과 실제 공개는 별도 상태로 기록한다. 제출 시점의 공식 요구사항을 다시 확인한다.
