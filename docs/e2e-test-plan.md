# molsino Blackjack E2E 테스트 설계 — MVP 목표

버전: 0.3 · 작성일: 2026-09-15 · 갱신일: 2026-09-17 · 상태: S10 및 macOS E2E Dock 회귀 완료, 전체 MVP E2E 대기

기준 문서: [제품 설계서](blackjack-design.md) §6 3단계 "플레이 가능한 MVP", [기술 설계서](blackjack-technical-design.md) §11.2·§11.4. 현재 구현 상태는 `AGENT.md` 참조.

## 1. 목적과 범위

이 문서는 **MVP 완료 기준**(제품 설계서 §6, 3단계)을 검증하는 E2E 시나리오를 정의한다.

> 최초 $100에서 $1 이상 베팅해 여러 판을 끝낼 수 있고, 라운드 중 종료 후 재실행해도 같은 카드와 잔액으로 이어진다. 히트 전후·보험 선택 전후와 정산 후·스플릿 핸드 사이·더블 후·딜러 진행 중·정산 직후·판 사이 슈의 저장 복원을 검증한다.

범위는 기술 설계서 §11.4의 **P1(엔진) + P2(GameStore·IPC·UI·저장 통합)**다. E2E-18만 게임 세션 복원과 창 설정 재실행 초기화의 경계를 확인한다. 나머지 P0 창 프로토타입 항목(O-01~O-11: 리사이즈, 클릭 통과, 다중 모니터 등)과 P3(장애 복구 전면, 접근성, DPI, 성능, 설치본 서명)는 이 문서의 대상이 아니다 — §6에서 별도 표기.

### 테스트 계층 구분

같은 규칙을 두 계층에서 중복 검증하지 않는다.

| 계층 | 도구 | 대상 | 개수/속도 |
| --- | --- | --- | --- |
| 엔진·저장·IPC 신뢰 경계 | Vitest | `BlackjackCore` 순수 함수, 정산 원장, `SessionRepository` 원자 저장, IPC sender/스키마 검증 | 다수, 빠름 — 기술 설계서 §11.2 목록 전부 여기 소속 |
| 사용자 여정 (배관 검증) | Playwright `_electron` | 실제 앱 프로세스: Renderer 클릭 → Preload → Main IPC → GameStore → 엔진 → 저장 → 화면 반영 | 소수, 느림 — 이 문서의 시나리오 |

E2E는 규칙의 모든 조합(예: 모든 배당 표 행, A 재스플릿 금지의 모든 경로)을 다시 검증하지 않는다. 각 주요 분기(블랙잭, 보험, 이븐 머니, 더블, 스플릿, 서렌더)당 **대표 경로 1개**만 실제 UI로 통과시켜 "전체 스택이 올바르게 연결됐다"를 증명하고, 세부 규칙 조합은 Vitest 픽스처가 책임진다.

## 2. 테스트 인프라 상태

순수 코어의 불변 Shoe와 주입형 RNG·ID 경계를 실제 Main/IPC/Renderer 경로까지 연결했다. S08에서 저장 파일 사전 조작과 재기동·강제 종료 검증을 추가했다.

| 훅 | 목적 | 제안 |
| --- | --- | --- |
| 격리된 `userData` | 테스트 간 저장 파일 충돌 방지, 병렬 실행 | ✅ `MOLSINO_TEST_USER_DATA`로 구현 |
| 결정론적 슈 주입 | 특정 카드 시퀀스(블랙잭, 버스트, 페어 등)를 앱 전체 레벨에서 재현 | ✅ `BLACKJACK_TEST_SHOE_FIXTURE`와 `EngineEnvironment.createShoe` 연결 |
| 확장된 `getSnapshot`/`onState` | 판 상태를 화면 밖에서 단언 | ✅ 실제 `GameViewState`와 revision 기반 구독 구현 |
| `dispatch` 커맨드 확장 | UI 없이도 명령 실행/검증 가능 | ✅ 모든 사용자 행동과 strict Zod 계약 구현 |
| 강제 종료 → 재기동 헬퍼 | 저장 복원 시나리오 | ✅ 동일 `userData`로 정상 종료·SIGKILL 재기동 대표 경로 구현 |
| 저장 파일 사전 조작 | 손상/미래 스키마 시나리오 | ✅ 테스트 프로세스(Node)가 재기동 전에 `session.json`을 직접 조작 |
| macOS E2E Dock 아이콘 | 매 테스트 앱 실행의 Dock 잔류 방지 | ✅ 테스트 앱에만 `MOLSINO_TEST_HIDE_DOCK=1`을 전달. `dock-lifecycle.spec.ts`에서 `app.dock.isVisible() === false` 확인. 일반 앱과 OS Dock 설정은 변경하지 않음 |

현재 대표 자연 블랙잭 여정, S08 저장 복원 6건, S09 IPC·보안 회귀 5건이 실제 패키지에서 자동화됐다. E2E-17의 나머지 체크포인트와 E2E-18은 S15/S11에서 완성한다.

## 6. 범위 밖과 P0 보조 스위트

- E2E-01~21의 범위에서는 P0 창 프로토타입 O-01~O-11을 제외한다. 다만 각 P0 작업 세션은 별도의 보조 spec을 추가한다. S01 `overlay-resize.spec.ts` 4건은 핸들→IPC→Main→실제 BrowserWindow bounds, min/max clamp, token 만료, 220×150 레이아웃을 검증한다. S10 `overlay-state.spec.ts` 9건은 내부 접힘·펼침, 판 보존·숨김/접힘 중 딜러 계속 진행, 색상 버튼 호버 조절창의 슬라이더 기본값·20/100% 경계·즉시 반영·접힘 중 유지·재실행 초기화·화면 경계 방향 선택·호버 유지/닫힘·게임/창 명령 차단, 헤더 `▁` 버튼 부재와 전역 Alt+백틱 등록·숨김 상태에서 재숨김·복원 경로를 검증한다.
- Playwright Electron으로 실제 외부 앱 포커스 이동, 물리 Alt+백틱 입력, 투명도 합성, 클릭 통과 대상 앱 반응, 물리 다중 모니터를 확인할 수 없으면 통과로 추정하지 않고 관련 이슈로 기록한다.
- P3: 접근성 창(키보드/VoiceOver/Narrator), DPI, 성능 목표(§11.3), 설치본 서명·공증.
- Windows 실 장비 검증 (CI는 빌드만, GUI 동작은 실 장비 필요 — AGENT.md 검증 기록 참조).

## 7. 실행 계획

- 디렉터리: 기술 설계서 §10 구조를 따라 `tests/e2e/*.spec.ts`.
- `@playwright/test` 1.59.1과 `tests/e2e` TypeScript 구성이 설치되어 있으며, `overlay-resize.spec.ts`가 프로덕션 패키지에서 실행된다.
- `playable-mvp.spec.ts`가 결정론적 슈로 베팅→딜→자연 블랙잭→다음 판의 전체 배관을 검증한다.
- `package.json`의 `test:e2e`는 `pretest:e2e`에서 Forge package를 만든 뒤 Playwright를 실행한다.
- CI(`ci.yml`)는 현재 `check + package`만 실행한다. E2E는 GUI가 필요한 Electron 창을 띄우므로 macOS/Windows GitHub Actions 러너에서 실제로 동작하는지 별도 확인이 필요하다(헤드리스 불가 가능성 — 현재 `smoke.cjs`도 "GUI 세션 필요"로 명시됨). 우선 로컬/수동 CI 잡으로 시작하고, 안정화 후 필수 게이트로 승격을 제안한다.
